# Requirements: Writ Compiler

**Defined:** 2026-03-27
**Core Value:** Correct, spec-compliant implementation at every layer — lowering matches Section 28 exactly, runtime matches the IL spec exactly — structured so each layer can be extended independently.

## v10.0 Requirements

Requirements for attribute system completion and user-defined attributes. Each maps to roadmap phases.

### Attribute Serialization

- [x] **BLOB-01**: Attribute arguments are encoded into the blob heap using a tagged format (string → UTF-8, int → i64 LE, bool → u8, named args → name + value)
- [x] **BLOB-02**: Attribute arguments can be decoded from the blob heap back to their original types and names (round-trip fidelity)
- [x] **BLOB-03**: Shared tag constants defined in `writ-module` used by both encoder and decoder

### Builtin Semantic Effects

- [x] **DEPR-01**: Referencing a `[Deprecated("msg")]` item produces a compiler warning containing the user's message string
- [x] **DEPR-02**: LSP surfaces `[Deprecated]` as `DiagnosticSeverity::Warning` and shows the deprecation message on hover
- [x] **COND-01**: `[Conditional("name")]` function emits only the winning variant when condition is active via `writ.toml` or `--condition` flag
- [x] **COND-02**: When no condition is active, the non-conditional fallback function is emitted
- [x] **COND-03**: Resolver verifies fallback exists with matching signature; emitter errors on multiple conditions matching the same signature
- [x] **COND-04**: Arguments at a `[Conditional]` call site still type-check even when the call is elided
- [x] **SPKR-01**: `@speaker` reference in a dialogue block targeting a non-`[Singleton]` entity produces E0007
- [x] **SPKR-02**: `@speaker` reference targeting a non-existent entity produces an error

### User-Defined Attributes

- [x] **UATTR-01**: User can declare attributes with typed parameters using `attribute Name(args);` syntax
- [x] **UATTR-02**: User-defined attributes pass through the pipeline and appear in the module's AttributeDef table with serialized arguments
- [x] **UATTR-03**: Builtin attributes (`[Deprecated]`, `[Conditional]`, `[Singleton]`, `[Locale]`) are registered in the writ-runtime virtual module namespace
- [x] **UATTR-04**: Builtin attribute names are reserved; user-defined attributes with the same name produce a name collision error

### Runtime Query API

- [x] **QAPI-01**: Runtime exposes `query_attributes(name)` returning all matching declarations with decoded arguments
- [x] **QAPI-02**: Runtime exposes `query_attributes_on(type_id)` returning all attributes on a specific type
- [x] **QAPI-03**: Runtime exposes `query_attribute_value(def, name)` returning decoded args for a specific attribute on a specific definition
- [x] **QAPI-04**: Runtime provides a pre-load callback that fires before any module code executes, giving the host full attribute inspection
- [x] **QAPI-05**: Pre-load callback returns allow/reject decision; rejected modules are not loaded
- [x] **QAPI-06**: No attribute causes automatic instantiation or invocation — host must explicitly act on query results

### Tooling & Spec

- [x] **TOOL-01**: LSP E2E tests cover attribute diagnostics (deprecated warnings, speaker validation errors)
- [x] **TOOL-02**: Golden files are updated/reblessed for attribute pipeline changes
- [x] **TOOL-03**: Language spec is updated to document attribute argument encoding, user-defined attributes, and runtime query API

## Future Requirements

### Standard Library Attributes
- **STDLIB-01**: Standard attribute types for common patterns (e.g., `[Serializable]`, `[TestOnly]`)

## Out of Scope

| Feature | Reason |
|---------|--------|
| Reflection system | Attributes are metadata, not a general reflection API — host gets structured query, not arbitrary type access |
| Attribute inheritance | Attributes do not propagate to derived types or overriding methods |
| Runtime attribute creation | Attributes are compile-time metadata only; no dynamic attribute attachment |
| Attribute targets/constraints | Restricting which declarations an attribute can be placed on (e.g., methods-only) — future enhancement |
| Custom attribute validation logic | User-defined attributes have no custom validation hooks; type checking covers arg types |

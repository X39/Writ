## Phase Details

### Phase 100: Spec and IL Foundation
**Goal**: The language spec defines all reflection semantics and the IL opcode is assigned — every downstream implementation phase has a stable written contract to implement against
**Depends on**: Nothing (first phase of v11.0)
**Requirements**: SPEC-01, SPEC-02, SPEC-03, SPEC-04, SPEC-05, SPEC-06, SPEC-07, SPEC-08
**Success Criteria** (what must be TRUE):
  1. A reader of the spec can find a complete §1.X Reflection section describing Type, FieldInfo, MethodInfo, ParameterInfo, AttributeInfo, ContractInfo with their fields and methods
  2. The spec clearly distinguishes typeof(expr) (static compile-time query) from expr.get_type() (dynamic runtime query), with an example showing they diverge for polymorphic variables
  3. The Reflectable contract is defined with its single get_type() -> Type method and the rule that it is auto-implemented on all user-defined types
  4. Dynamic invocation semantics are specified: FieldInfo.set() crashes the task on let-field violation, MethodInfo.invoke() uses the current task stack
  5. §4.2 opcode table contains TypeOf with its assigned opcode number; §2.18 virtual module spec lists the 6 reflection types and Reflectable as contract 19; format_version 4 is documented
**Plans**: 2 plans
Plans:
- [x] 100-01-PLAN.md — Write section 1.28 Reflection spec, rename grammar/lowering sections, update TOC
- [x] 100-02-PLAN.md — Add TypeOf opcode, format_version 4, writ-runtime Reflection Types section

### Phase 101: writ-module TypeOf Instruction and Format Version Bump
**Goal**: The binary module format supports the TypeOf instruction and rejects old-format modules — compiler and runtime can both encode and decode modules with reflection instructions
**Depends on**: Phase 100
**Requirements**: SPEC-05, SPEC-06
**Success Criteria** (what must be TRUE):
  1. A module containing a TypeOf instruction round-trips through the writ-module writer and reader with bit-for-bit identity
  2. A module with format_version=3 produces an UnsupportedVersion error when loaded — old binaries are never silently misinterpreted
  3. The writ-assembler accepts the `typeof` mnemonic and the disassembler emits it correctly
  4. `cargo test` passes with zero failures across writ-module and writ-assembler crates
**Plans**: 1 plan
Plans:
- [x] 101-01-PLAN.md — Add TypeOf instruction to binary format and assembler/disassembler

### Phase 102: writ-runtime Virtual Module Reflection Types
**Goal**: Scripts can reference Type, FieldInfo, MethodInfo, ParameterInfo, AttributeInfo, and ContractInfo as known types, and the Reflectable contract exists as contract 19 in every loaded domain
**Depends on**: Phase 101
**Requirements**: TYPE-01, TYPE-02, TYPE-03, TYPE-04, TYPE-05, TYPE-06, TYPE-07, TYPE-08
**Success Criteria** (what must be TRUE):
  1. A hand-assembled module that calls get_type() on an Int value dispatches to IntrinsicId::IntGetType without a panic or unresolved-dispatch error
  2. The virtual module lists exactly 6 new class TypeDefs (Type, FieldInfo, MethodInfo, ParameterInfo, AttributeInfo, ContractInfo) with the fields specified in the spec
  3. Reflectable appears as contract index 19 in the domain dispatch table with one method slot (get_type)
  4. Primitive get_type intrinsics (IntGetType, FloatGetType, BoolGetType, StringGetType) are registered and return a non-null value without panicking
  5. `cargo test` passes with zero failures in writ-runtime
**Plans**: 1 plan

### Phase 103: writ-runtime ReflectionIndex and Intrinsic Dispatch
**Goal**: Runtime reflection metadata is lazily loaded and correctly GC-rooted — scripts can call Type.fields(), Type.methods(), Type.attributes(), Type.contracts(), Type.implements(), and FieldInfo.get() without crashing or returning stale data after a GC cycle
**Depends on**: Phase 102
**Requirements**: RT-01, RT-02, RT-03, RT-04, RT-05
**Success Criteria** (what must be TRUE):
  1. A hand-assembled test module calls Type.fields() on a user struct and the returned array contains one FieldInfo per public field with correct name and declared_type values
  2. After triggering a manual GC cycle with no script-side roots, cached Type heap objects are still valid and scripts can call methods on them — they are not freed
  3. TypeOf opcode dispatch in the VM main loop returns a Type heap object for any type index without panicking
  4. All 28+ reflection IntrinsicId arms dispatch without a match panic; unimplemented arms return a clear error or stub rather than silently returning garbage
  5. AttributeInfo objects produced by Type.attributes() are populated using the unified AttributeIndex that shares data with the v10.0 ModuleAttributeView
**Plans**: 2 plans
Plans:
- [x] 103-01-PLAN.md — ReflectionIndex, GC roots, ExecContext wiring, TypeOf and primitive GetType dispatch
- [x] 103-02-PLAN.md — IntrinsicId variants, reflection intrinsic dispatch arms, integration tests

### Phase 104: writ-compiler typeof() Lowering and TyKind
**Goal**: A Writ source file using typeof(expr) compiles to a module with the TypeOf instruction baked in, and the type checker assigns TyKind::ReflectionType(Type) to typeof expressions
**Depends on**: Phase 103
**Requirements**: COMP-01, COMP-02, COMP-04, COMP-05, REFL-01
**Success Criteria** (what must be TRUE):
  1. `typeof(x)` in Writ source lowers to AstExpr::TypeOf (not a function call node) — confirmed by inspecting the lowered AST in a lowering snapshot test
  2. The type checker assigns TyKind::ReflectionType(Type) to any typeof(expr) expression and an incorrect use (e.g. adding an int to a typeof result) produces a type error
  3. The compiler emits the TypeOf instruction with the correct compile-time type index baked in — confirmed by disassembling the compiled module
  4. Passing a reflection type value to a reflection API parameter auto-inserts BOX/UNBOX coercions without requiring the script author to write them
  5. `cargo test` passes with zero failures in writ-compiler; the golden test suite passes without regressions
**Plans**: 2 plans
Plans:
- [x] 104-01-PLAN.md — Lexer keyword, CST/AST variants, lowering, TyKind::ReflectionType, type checker arm
- [x] 104-02-PLAN.md — TypeRef registration, TypeOf IL emission, type_sig encoding

### Phase 107: Dynamic Invocation
**Goal**: Scripts can write fields and invoke methods dynamically through reflection, with runtime enforcement of let-field immutability and correct participation in cooperative scheduling
**Depends on**: Phase 106
**Requirements**: DYN-01, DYN-02, DYN-04 (DYN-03 deferred to v12+)
**Success Criteria** (what must be TRUE):

  2. FieldInfo.set() on a mut-declared field successfully writes the new value — confirmed by a test that reads back the field value after the set
  3. MethodInfo.invoke() correctly executes a method on the current task's call stack — confirmed by a test where an invoked method modifies instance state
  4. MethodInfo.invoke() participates in cooperative scheduling — confirmed by an instruction-limited tick test
**Plans**: 2 plans

### Phase 108: Generic Reflection
**Goal**: Scripts can query generic type information for statically-known instantiations, and the spec documents the exact boundary of what type_args() promises for runtime-queried types
**Depends on**: Phase 107
**Requirements**: GEN-01, GEN-02, GEN-03, GEN-04
**Success Criteria** (what must be TRUE):
  1. Type.is_generic returns true for a generic type instantiation (e.g. Array<Int>) and false for a non-generic type
  2. Type.type_args() returns the correct array of Type values for a statically-known generic instantiation (e.g. [Int] for Array<Int>)
  3. MethodInfo.attributes() and FieldInfo.attributes() return correctly populated AttributeInfo arrays — verified by a golden test on a type with per-member attributes
  4. The spec section on generic reflection documents the limitation: type_args() for runtime-queried generics (via get_type()) returns partial or empty info, not a silent empty array without explanation
**Plans**: 2 plans

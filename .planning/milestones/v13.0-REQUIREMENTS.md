# Requirements: Writ v13.0 Standard Library & Language Ergonomics

**Defined:** 2026-03-29
**Core Value:** Correct, spec-compliant implementation at every layer — lowering matches Section 28 exactly, runtime matches the IL spec exactly — structured so each layer can be extended independently.

## v13.0 Requirements

### Generic Constraints

- [x] **GEN-01**: User can declare single contract bounds on generic type params (`<T: Eq>`)
- [x] **GEN-02**: User can declare multiple contract bounds on a single type param (`<T: Eq + Ord>`)
- [x] **GEN-03**: Compiler enforces bounds at call sites — error when passing a type that doesn't implement the required contract
- [x] **GEN-04**: Compiler emits generic constraints to IL GenericConstraint table rows
- [x] **GEN-05**: Constraint violation errors show multi-span diagnostics (call site + constraint declaration)
- [x] **GEN-06**: Constraint violation errors include fix suggestion ("add `impl Eq for Foo`")

### Collections

- [x] **COLL-01**: User can create and use `List<T>` with add(item), get(i), len(), remove_at(i), has(item) operations
- [x] **COLL-02**: User can create and use `Map<K, V>` with get(k), set(k, v), has(k), remove(k), len() operations (O(n) linear scan for v13.0; O(log n) sorted-array is a future optimization)
- [x] **COLL-03**: User can create and use `Set<T>` with add(v), remove(v), has(v), len()
- [x] **COLL-04**: User can chain `list.map(fn).filter(fn).reduce(fn)` higher-order methods on List<T>
- [x] **COLL-05**: User can create and use hash-based `HashMap<K, V>` with Hashable contract for O(1) average lookup
- [x] **COLL-06**: All collections written in pure Writ source, loaded as library modules

### String Utilities

- [x] **STR-01**: User can call `string.split(sep)` to split a string into an array
- [x] **STR-02**: User can call `string.trim()` to remove leading/trailing whitespace
- [x] **STR-03**: User can call `string.starts_with(prefix)` and `string.ends_with(suffix)`
- [x] **STR-04**: User can call `string.contains(substr)` to check substring presence
- [x] **STR-05**: User can call `string.replace(from, to)` to replace occurrences
- [x] **STR-06**: User can call `string.to_upper()` and `string.to_lower()` for case conversion

### Iterator Protocol

- [x] **ITER-01**: User can write `for x in list` and it works via Iterable<T> contract desugaring
- [x] **ITER-02**: User can write `for x in set` and it works via Iterable<T>
- [x] **ITER-03**: User can write `for k in map.keys()` and `for v in map.values()` to iterate Map entries
- [x] **ITER-04**: User can implement `Iterable<T>` on custom types and use them in for-in loops
- [x] **ITER-05**: List<T>, Map<K,V>, Set<T> all implement Iterable<T>

### Host Value Construction

- [x] **HOST-01**: Host Rust code can construct a Writ struct/class value by name with runtime type validation (field count, field types checked against module metadata)
- [x] **HOST-02**: Host Rust code can construct values in immediate extern handlers (heap access provided)
- [x] **HOST-03**: Runtime returns a clear error when host constructs a value with wrong field count or mismatched field types

### Diagnostics Polish

- [x] **DIAG-01**: Constraint violation errors show both call site and constraint declaration spans
- [x] **DIAG-02**: Errors include fix suggestions with concrete code snippets
- [x] **DIAG-03**: `--deny-warnings` CLI flag treats warnings as errors
- [x] **DIAG-04**: LSP provides completions and hover on files with syntax errors (partial parse recovery)

## Future Requirements

### Collections v2

- **COLL-07**: User can call `list.sort()` with `T: Ord` bound enforcement
- **COLL-08**: User can use `EntityList<T>` for typed entity reference collections

### Iterators v2

- **ITER-06**: User can create lazy iterator chains (Sequence protocol) that evaluate on demand
- **ITER-07**: User can write custom Iterator<T> implementations with heap-allocated cursor state

### Host Interop v2

- **HOST-04**: Convenience derive macro (`#[derive(WritType)]`) that auto-maps Rust structs to Writ types, generating extern fn registrations and type-safe value construction/extraction
- **HOST-05**: Host can create a Writ library module from Rust code directly (Rust-backed writ-std alternative for performance-critical paths)

### Diagnostics v2

- **DIAG-05**: Warning suppression pragmas (`#[allow(W0006)]`) per-item
- **DIAG-06**: LSP autocomplete for partially-typed generic type arguments (`List<T` mid-edit)

## Out of Scope

| Feature | Reason |
|---------|--------|
| Rust-backed (extern) collection implementations | Blocks reflection/serialization from inspecting internals; pure Writ preferred |
| `any`-typed heterogeneous collections | Destroys type safety; use `any[]` at reflection boundaries instead |
| `.sort()` on List<T> | Requires non-trivial O(n log n) algorithm in Writ; defer to v14.0 |
| Warning suppression pragmas | New pragma parsing path; fix false positives at source instead |
| Lazy iterator chains | Requires coroutine suspension or closure-based approach; ship eager methods first |
| Partial generic type arg LSP completion | Parser disambiguation for `<` is ambiguous mid-edit; defer to v14.0+ |

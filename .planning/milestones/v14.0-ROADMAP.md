## Phase Details

### Phase 120: Array Semantics Correction
**Goal**: T[] is a fixed-size array — growth methods removed, resize and copy are the explicit reallocation operations, and the spec matches
**Depends on**: Nothing (independent compiler + spec change)
**Requirements**: ARR-01, ARR-02, ARR-03, ARR-04, ARR-05, ARR-06
**Success Criteria** (what must be TRUE):
  1. User code calling `arr.add(x)`, `arr.remove_at(i)`, or `arr.insert(i, x)` on a `T[]` value produces a compiler error naming the unknown method
  2. User can call `arr.resize(n)` to reallocate the array to a new fixed size and subsequently access indices 0..n
  3. User can call `arr.copy(dst_idx, src, src_idx, len)` to bulk-transfer elements between two arrays
  4. User can call `arr.len()`, `arr.slice(start, end)`, and indexed access on any `T[]` — these are the only built-in operations
  5. The language spec describes T[] as fixed-size with resize/copy as explicit operations; docs for add/remove_at/insert/contains are removed
**Plans:** 3/3 plans complete
Plans:
- [x] 120-01-PLAN.md — Module instruction enum overhaul + format_version bump
- [x] 120-02-PLAN.md — Compiler, runtime, and assembler wiring for new opcodes
- [x] 120-03-PLAN.md — Golden test fixtures, collection test ignoring, and spec rewrite

### Phase 121: Stdlib Rewrite
**Goal**: List<T>, Map<K,V>, Set<T>, and HashMap<K,V> internals use only the fixed-size array API and all collection tests pass
**Depends on**: Phase 120 (resize+indexed assignment API must exist before stdlib can be rewritten against it)
**Requirements**: STD-01, STD-02, STD-03, STD-04, STD-05
**Success Criteria** (what must be TRUE):
  1. The List<T> Writ source uses only `resize`, indexed assignment, `len`, and `slice` internally — no calls to `add`, `remove_at`, or `insert` on any backing array
  2. The Map<K,V>, Set<T>, and HashMap<K,V> Writ sources likewise use only the fixed-size array API internally
  3. All existing collection integration tests pass with the rewritten internals — push, pop, get, set, contains, keys, values, map, filter, reduce all produce correct results
  4. The writ-std library module compiles cleanly with no warnings
**Plans:** 2/2 plans complete
Plans:
- [x] 121-01-PLAN.md — Rewrite all four collection classes to use fixed-size array API
- [x] 121-02-PLAN.md — Un-ignore golden tests, re-bless IL snapshots, verify suite passes

### Phase 122: Cross-Module Type Resolution
**Goal**: The compiler can load type definitions from a pre-compiled .writc module and validate user references against them at compile time
**Depends on**: Nothing (independent of array work; DefMap extension is a separate compiler subsystem)
**Requirements**: XMOD-01, XMOD-02, XMOD-03, XMOD-04, XMOD-05, XMOD-06
**Success Criteria** (what must be TRUE):
  1. User code that references a type from a pre-compiled `.writc` library module (added to `writ.toml` as a dependency) compiles without error and produces correct IL
  2. User code that references a non-existent type from a library module gets a clear name-resolution error at compile time — not a runtime panic
  3. Virtual module types (Type, FieldInfo, MethodInfo, etc.) are resolvable through the same DefMap mechanism as user library modules — no special-casing
  4. The `coll_with_library_separate_modules` integration test passes with the `#[ignore]` attribute removed
  5. The language spec documents cross-module type resolution, the `.writc` dependency mechanism, and how `using` declarations surface library types
  6. Integration tests cover at least: successful type reference, method call on library type, field access, and a type-not-found error path
**Plans:** 3/3 plans complete
Plans:
- [x] 122-01-PLAN.md — Core DefMap injection + TypeEnv method sig reconstruction + compile_with_libraries API
- [x] 122-02-PLAN.md — Config/CLI wiring, virtual module injection, integration tests, un-ignore proof test
- [x] 122-03-PLAN.md — Language spec documentation for cross-module resolution

# Requirements: Writ Compiler v3.2

**Defined:** 2026-03-06
**Core Value:** Correct, spec-compliant implementation at every layer — lowering matches Section 28 exactly, runtime matches the IL spec exactly — structured so each layer can be extended independently.

## v3.2 Requirements

Requirements for language spec corrections, semantic conflict resolution, compiler tooling additions, and a design discussion.

### Spec Corrections

- [x] **SPEC-01**: Spec §1.2.8 (Serialization Critical Sections) is removed — section contains invalid claims about atomic blocks and native resources
- [x] **SPEC-02**: Spec clarifies that inbuilt methods (`log`, `say`, `choice`) live in the root namespace and are always accessible without qualification
- [x] **SPEC-03**: `writ.toml` field names in spec, `config.rs`, and `writ new` scaffold are aligned (`locale.default`, `locale.supported`, consistent sources directory)

### Language Semantics

- [x] **LANG-01**: The dialogue choice option type is renamed from `Option(...)` to `ChoiceOption(...)` in spec and implementation (lowering, virtual module, prelude) — resolves naming conflict with `Option<T>`
- [x] **LANG-02**: User can write `None` and `Some(value)` without `Option::` prefix — resolver injects both as sub-prelude symbols that do not shadow user-defined names

### Bug Fixes

- [x] **BUG-01**: `fn_log_say_choice` golden test codegen failure is diagnosed and fixed — method bodies are non-empty; snapshot re-blessed with spec-correct IL in UTF-8 encoding

### Tooling

- [x] **TOOL-01**: User can compile a Writ project by running `writ compile .` or `writ build` in a directory containing `writ.toml` — all `.writ` files from the configured sources directory are compiled into one module
- [x] **TOOL-02**: `--release` and `--debug` flags are supported on `writ compile`/`writ build` — `[profile.release]` and `[profile.debug]` in `writ.toml` are respected
- [x] **TOOL-03**: User calls `log.debug(msg)`, `log.info(msg)`, `log.warn(msg)`, `log.error(msg)` from Writ scripts — the unqualified `log(msg)` one-argument form is removed; all logging uses the leveled namespace

### Design Discussion

- [x] **DES-01**: Spec amendment section on structs-as-value-types exists with a written decision record covering YES/NO/MAYBE paths, GC implications, and a v4.0 scope if YES

## Future Requirements

Deferred to v3.3+.

### Tooling

- **TOOL-04**: User can specify source globs in `writ.toml` — additive after multi-file compilation is stable
- **TOOL-05**: `log.debug(msg, category)` — optional category string for engine-side routing; after log levels are stable

## Out of Scope

| Feature | Reason |
|---------|--------|
| Structs as value types (implementation) | Cross-cutting VM change; v3.2 produces design record only — implementation is v4.0 |
| `log(msg)` one-argument form | Removed in v3.2 in favor of leveled log.debug/info/warn/error |
| `--no-writ-toml` flag | Not needed — single-file `writ compile foo.writ` already handles this |
| Hot-reload / watch mode | Requires incremental compilation infrastructure |
| Standard library (writ-std) | Explicitly deferred per PROJECT.md |
| Escaped braces (`{{`/`}}`) | Lexer gap in writ-parser — not in scope |
| TYPE-12 closure captures | Deferred per v3.0 decision |

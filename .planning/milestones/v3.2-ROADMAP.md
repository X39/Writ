### Phase 40: Spec Cleanup
**Goal**: The language spec is internally consistent — §1.2.8 is removed, inbuilt method call paths are clarified, and writ.toml field names in spec, config.rs, and writ new scaffold are aligned
**Depends on**: Phase 39 (v3.1 complete)
**Requirements**: SPEC-01, SPEC-02, SPEC-03
**Success Criteria** (what must be TRUE):
  1. §1.2.8 Serialization Critical Sections no longer exists in the spec — the section is deleted and surrounding numbering is updated
  2. A spec section explicitly states that `log`, `say`, and `choice` are root-namespace inbuilt calls — no qualification needed, callable as `log(msg)` not `writ::log(msg)`
  3. The `writ.toml` spec fields (`locale.default`, `locale.supported`, `sources`) exactly match the Rust struct field names (with `#[serde(rename)]` if needed) and the `writ new` scaffold produces a file that `load_config` deserializes without error

### Phase 42: ChoiceOption Rename
**Goal**: The dialogue choice option type is named `ChoiceOption` everywhere — spec text, lowering emit site, virtual module TypeDef/ExternDef, and resolver prelude — resolving the naming conflict with `Option<T>`
**Depends on**: Phase 41
**Requirements**: LANG-01
**Success Criteria** (what must be TRUE):
  1. The string `"Option"` no longer appears as a choice constructor name in any spec section, Rust source file, or golden test fixture — replaced by `"ChoiceOption"` in all four layers atomically
  2. All existing golden tests that reference `ChoiceOption` (including the re-blessed fn_log_say_choice) pass after the rename
  3. A Writ script using `$ choice { ... }` compiles and the emitted CALL_EXTERN references the `ChoiceOption` ExternDef token
**Plans**: 1 plan

Plans:
- [ ] 42-01-PLAN.md — Rename emit site + spec, bless four snapshots, add choice_option_emits_externdef integration test

### Phase 43: Unqualified None/Some
**Goal**: Writ scripts can use `None` and `Some(value)` without the `Option::` prefix — the resolver injects both as symbols at lower priority than user-defined names
**Depends on**: Phase 42
**Requirements**: LANG-02
**Success Criteria** (what must be TRUE):
  1. `let x: bool? = None;` compiles without error and emits `LOAD_NULL` — no `Option::` prefix required
  2. `let y = Some(true);` compiles without error and emits `WRAP_SOME` — no `Option::` prefix required
  3. A user-defined variable or type named `None` or `Some` shadows the injected symbol without a compile error — user definitions take priority
  4. `Option::None` and `Option::Some(value)` continue to compile correctly — the qualified path still resolves
**Plans**: 3 plans

Plans:
- [ ] 43-01-PLAN.md -- Test stubs: Wave 0 Nyquist stubs for all LANG-02 behaviors
- [ ] 43-02-PLAN.md -- Resolver layer: BuiltinVariant injection + using Enum::* glob expansion
- [ ] 43-03-PLAN.md -- Check layer + parser ::* + spec subsection

### Phase 44: Extended Log with Levels
**Goal**: Writ scripts use the leveled log namespace (`log::trace`, `log::debug`, `log::info`, `log::warn`, `log::error`) — the old unqualified `log(msg)` one-argument form is removed and replaced with the leveled API
**Depends on**: Phase 43
**Requirements**: TOOL-03
**Success Criteria** (what must be TRUE):
  1. `log::debug("msg")`, `log::info("msg")`, `log::warn("msg")`, `log::error("msg")` each compile without error and route to `RuntimeHost::on_log` with the correct `LogLevel` variant
  2. `log("msg")` (unqualified one-argument form) no longer compiles — callers must use the leveled API
  3. The spec documents the leveled log API as the sole logging interface, with `log(msg)` removed
  4. CliHost prints the log level prefix (e.g., `[DEBUG]`, `[WARN]`) alongside the message for each level
  5. All existing golden test fixtures and example code that use `log(msg)` are updated to use `log::info(msg)`
**Plans**: 2 plans

Plans:
- [ ] 44-01-PLAN.md — Compiler pipeline: resolver ExternFn injection, TypeEnv FnSig injection, check_call two-segment log fast-path, emitter ExternDef injection
- [ ] 44-02-PLAN.md — CliHost dispatch, fixture migration (golden + parser + CLI), spec update, golden re-bless

### Phase 45: writ.toml Project File Compilation
**Goal**: Running `writ build` in a directory containing `writ.toml` compiles all .writ source files into one module; `--release` and `--debug` flags are respected
**Depends on**: Phase 40
**Requirements**: TOOL-01, TOOL-02
**Success Criteria** (what must be TRUE):
  1. `writ build` in a directory with `writ.toml` discovers all `.writ` files under the configured sources directory and compiles them into a single output module — no manual file listing required
  2. `writ build --release` compiles with `[profile.release]` settings from `writ.toml`; `writ build --debug` (or omitting the flag) uses `[profile.debug]` settings
  3. A project scaffolded by `writ new` can be compiled immediately with `writ build` without any manual writ.toml editing — the `sources/` default matches the scaffold layout
  4. Passing a single `.writ` file path to `writ compile foo.writ` continues to work exactly as before — single-file mode is unaffected
  5. Output path follows `{output_base}/{profile}/{name}.writc` — e.g., `build/debug/my-game.writc`
**Plans**: 2 plans

Plans:
- [ ] 45-01-PLAN.md — ProfileConfig in config.rs, emit_debug_info gate in emit pipeline
- [ ] 45-02-PLAN.md — Build subcommand, pipeline refactor, cmd_new update, spec amendment

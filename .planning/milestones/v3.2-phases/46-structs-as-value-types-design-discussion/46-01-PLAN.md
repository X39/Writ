**File 1: `language-spec/spec/09_8_structs.md`** -- Append a new `### 8.4 Value-Type Structs and Classes -- Design Record (v4.0)` section after the existing `### 8.3 Construction Sequence` section. This section is the core deliverable. Structure it as follows:

**Section 8.4.1: Decision**
State: YES -- Writ will adopt a struct/class split in v4.0. `struct` becomes a value type (inline, copy-on-assign, no heap allocation for the struct itself). `class` becomes the new keyword for reference types (heap-allocated, GC-managed, shared-on-assign) -- this is what `struct` means today (v3.x). `entity` keeps its own keyword but is conceptually a specialized class (entity -> class, but class !-> entity).

**Section 8.4.2: New Type Semantics**
Include a table showing the three type keywords (struct, class, entity) with columns: Keyword, Kind, Storage, Assignment, GC Traced, Lifecycle Hooks. Use the exact values from RESEARCH.md "The Struct/Class Split" table:
- struct: Value, Register/inline, Shallow copy (copies all fields; ref fields copy pointer), Payload ref fields traced, None
- class: Reference, Heap (GC-managed), Copy reference (shared object), Yes, on create/finalize/serialize/deserialize
- entity: Reference (specialized class), Entity runtime + GC heap, Copy handle, Yes, on create/finalize/serialize/deserialize + on destroy/on interact

State explicitly: Both `struct` and `class` can implement contracts. Value-type structs get boxed through generics, same as enums.

**Section 8.4.3: Value-Type Struct Semantics**
Cover these subsections:
- **Shallow copy:** Assignment copies all fields by value; reference-typed fields copy the pointer (both copies share the same object). Include the Vec2 and Note examples from RESEARCH.md.
- **Structural equality:** Value-type structs auto-derive field-by-field equality (like enums). Two structs are equal iff all corresponding fields compare equal. Classes require explicit Eq contract implementation.
- **Passing semantics:** Always by-copy. When passed as a function argument, the callee receives a copy. `mut self` on a method mutates the local copy, not the caller's value. Identical to how int and float behave.
- **No lifecycle hooks:** Value-type structs have no `on create`, `on finalize`, `on serialize`, `on deserialize`. If lifecycle hooks are needed, use a class.
- **No size limit:** Trust the developer. No compiler warning for large value-type structs.
- **Recursive value-type structs are illegal:** Infinite size = compiler error. The compiler detects this by walking the type graph. Include the Bad/Node examples from RESEARCH.md.

**Section 8.4.4: Motivating Examples**
Include Vec2, Vec3, Color, Rect examples and the move_entity function showing clean functional style. Also include the assignment semantics contrast example (Vec2 copy vs Merchant class shared reference).

**Section 8.4.5: IL Changes Required (v4.0)**
Enumerate all seven IL changes from RESEARCH.md:
1. TypeDef.kind flag extension: add kind=4 (class), kind=0 reinterpreted as value struct. Table: 0=struct(value), 1=enum, 2=entity, 3=component, 4=class(reference). Note the semantic change from v3.x.
2. NEW instruction behavior: kind-dependent -- class (4) = heap alloc as today; struct (0) = in-place init, no heap alloc. Note the alternative (separate NEW_STRUCT opcode) and recommend kind-check approach.
3. MOV instruction: multi-word copy for value struct registers. Note spec already says registers are abstract typed slots and MOV is type-dependent. Two VM representation options: (a) single abstract struct register, (b) register flattening. Recommend option (a), consistent with enum handling.
4. GC tracing: value-type struct registers traced using same mechanism as enum payload tracing (section 2.15.5). GC reads register TypeRef, walks FieldDef list, traces ref fields. No new mechanism needed.
5. BOX/UNBOX: value-type structs join int/float/bool/enum as types requiring boxing through generics. Instructions unchanged; documentation update only.
6. Structural equality: recommend compiler-emitted field comparisons (option a) over a new STRUCT_EQ instruction (option b). Keep instruction set minimal, consistent with enum equality through match patterns.
7. format_version bump to 3 (minimum). Old .writil files incompatible. Pre-1.0, acceptable.

Include the IL encoding change example from RESEARCH.md (v3.x NEW+SET_FIELD heap alloc vs v4.0 inline init).

**Section 8.4.6: GC Implications**
Cover three topics:
- Tracing through value structs: ref fields in inline registers must be traced. Mechanism: same as enum payload tracing. Register type table (section 2.16.6) provides type info. The runtime applies existing enum-payload-tracing logic to value-type struct registers.
- Closure capture environments: compiler-generated `struct __closure_env_0` (section 2.9.3) must use `class` semantics in v4.0, since capture environments are reference types. Flag as known follow-on spec update.
- No GC finalization on value structs: not heap objects, storage reclaimed when enclosing scope exits. No finalization. Consistent with no-lifecycle-hooks decision.

Include the GC tracing example (Note struct with string field, register tracing walkthrough) from RESEARCH.md.

State: v4.0 is a breaking change. Single v4.0 milestone, phased internally (spec -> IL -> VM -> compiler -> tests). format_version bump, no backward compatibility.

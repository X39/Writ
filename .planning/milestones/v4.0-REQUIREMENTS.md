# Requirements: Writ Compiler

**Defined:** 2026-03-12
**Core Value:** Correct, spec-compliant implementation at every layer — lowering matches Section 28 exactly, runtime matches the IL spec exactly — structured so each layer can be extended independently.

## v4.0 Requirements

Requirements for the Structs as Value Types milestone. Each maps to roadmap phases.

### Spec Amendments

- [x] **SPEC-01**: Section 8 updated — `struct` documented as value type, `class` keyword for reference types, `entity` as specialized class
- [x] **SPEC-02**: Section 2.9.1 Memory Model table updated — Structs row changed to Value, new Classes row added as Reference
- [x] **SPEC-03**: Section 2.9.3 Closure captures updated — compiler-generated capture types use `class` keyword
- [x] **SPEC-04**: Section 2.11 Construction Model updated — NEW semantics documented as kind-dependent
- [x] **SPEC-05**: Section 2.15 IL Type System updated — register model for value-type struct registers
- [x] **SPEC-06**: Section 2.16.5 TypeDef table updated — kind=0 reinterpreted as value struct, kind=4 (class) added
- [x] **SPEC-07**: Section 3.1 MOV semantics updated — multi-word copy for value-struct registers
- [x] **SPEC-08**: Section 3.8 NEW instruction updated — kind-dependent heap vs inline behavior
- [x] **SPEC-09**: Section 3.15 BOX/UNBOX updated — scope extended to value-type structs
- [x] **SPEC-10**: Appendix B Decision Log updated — Structs row updated, Classes row added
- [x] **SPEC-11**: `class` keyword added to grammar

### IL Format

- [x] **IL-01**: TypeDef.kind=4 (class) added to module format reader/writer
- [x] **IL-02**: format_version bumped to 3
- [x] **IL-03**: Module reader/writer correctly handles kind=4 TypeDef entries round-trip

### VM Runtime

- [x] **VM-01**: Value-type struct inline register representation — no heap alloc for kind=0 structs
- [x] **VM-02**: MOV copies all fields for value-type struct registers (multi-word copy)
- [x] **VM-03**: NEW instruction kind-dependent — heap alloc for class (kind=4), inline init for struct (kind=0)
- [x] **VM-04**: GC traces through value-struct registers to find embedded reference fields
- [x] **VM-05**: BOX/UNBOX extended to handle value-type struct boxing through generics
- [x] **VM-06**: Class (kind=4) uses existing heap allocation path (current struct behavior preserved)

### Compiler

- [x] **COMP-01**: `class` keyword parsed — CST and AST support for class declarations
- [x] **COMP-02**: Value-struct codegen — inline initialization (no heap alloc) for struct construction
- [x] **COMP-03**: Class codegen — heap allocation for class construction (current struct behavior)
- [x] **COMP-04**: Recursive struct detection — infinite size error for self-referencing value-type structs
- [x] **COMP-05**: Structural equality emission — field-by-field comparison for value-type structs
- [x] **COMP-06**: ~~Entity lowering emits kind=4 (class)~~ Resolved by decision: entities remain kind=2 (Entity) — VM treats kind=2 and kind=4 identically for heap allocation; entity-specific features (SPAWN_ENTITY, component slots, lifecycle hooks) key off kind=2
- [x] **COMP-07**: Closure capture environments emit as class (kind=4), not struct (kind=0)

### Tests

- [x] **TEST-01**: Existing golden tests updated for format_version=3 and kind changes
- [x] **TEST-02**: New golden tests for value-type struct semantics (copy, equality, no lifecycle hooks)
- [x] **TEST-03**: New golden tests for class declaration and reference semantics
- [x] **TEST-04**: Recursive struct detection error test

## Out of Scope

| Feature | Reason |
|---------|--------|
| Deep clone / clone trait | Not in spec; shallow copy is the defined behavior |
| Struct size limits/warnings | Design record explicitly says "no size limit" |
| Custom equality operators for structs | Auto-derived structural equality only; explicit Eq via contracts on classes |
| Stack overflow detection for large structs | Trusted developer model per design record |
| NEW_STRUCT opcode | Design record recommends kind-check approach over opcode proliferation |
| STRUCT_EQ opcode | Design record recommends compiler-emitted field comparisons |

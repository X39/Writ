```rust
fn find_struct_decl<'a>(asts: &'a [(FileId, &Ast)], entry: &DefEntry) -> Option<&'a AstStructDecl> {
    for (file_id, ast) in asts {
        if *file_id != entry.file_id { continue; }
        for decl in &ast.items {
            if let AstDecl::Struct(s) = decl {
                if s.name == entry.name && s.name_span == entry.name_span { return Some(s); }
            }
        }
    }
    None
}
```

**Recursive struct detection (check/mod.rs):**

Add a `detect_recursive_structs` function that runs AFTER the type-check loop completes (after all `check_decl` calls) but before returning from `check()`. This function:

1. Collects all DefIds with `DefKind::Struct` (NOT Class, NOT ExternStruct, NOT Entity — only value-type structs can have infinite-size cycles).

2. For each struct DefId, performs a DFS walk through its field types:
   - Look up fields from `ctx.type_env.struct_fields.get(&def_id)`
   - For each field, resolve the type. If the field type is `TyKind::Struct(field_def_id)`, recursively check that struct's fields.
   - Track the DFS path as `Vec<(DefId, String)>` where String is the field name that led there.
   - If DFS encounters a DefId already in the current path, a cycle is found.
   - `TyKind::Class`, `TyKind::Entity`, `TyKind::Enum`, and all primitives are safe — they use heap indirection or are fixed-size. Only `TyKind::Struct` recurses.
   - Use a "visited" set (globally) to avoid re-checking structs already fully explored. Use an "in-path" set (per DFS) to detect cycles.

3. When a cycle is detected, emit a diagnostic error with:
   - Error message: `"recursive struct has infinite size: {chain}"`
   - Chain format: `"Foo contains Bar (field 'inner') which contains Foo (field 'parent')"`
   - Build the chain string from the DFS path between the first occurrence of the repeated DefId and the current position.
   - Help message: `"help: consider using 'class' instead of 'struct' for reference semantics"`
   - Use the struct's name_span from the DefEntry for the error span.

4. Call `detect_recursive_structs(&mut ctx)` in the `check()` function, after the decl-checking loop, before returning `(typed_ast, ctx.diags)`.

**Integration point (check/mod.rs):**
The function signature should be:
```rust
fn detect_recursive_structs(
    def_map: &DefMap,
    type_env: &TypeEnv,
    interner: &TyInterner,
    diags: &mut Vec<Diagnostic>,
)
```

It needs access to `def_map` (to iterate struct DefIds and get DefEntry names/spans), `type_env.struct_fields` (to get field types), and `interner` (to resolve TyKind from Ty). The function should be defined in check/mod.rs since it operates at the module level after all declarations are checked.

**Error type:** Use the existing `Diagnostic` error infrastructure. Look at how other compile errors are emitted in the check module (search for `ctx.diags.push` or `ctx.emit_error` patterns). The error should be a `Diagnostic` with appropriate span, message, and help text. If the project uses `TypeError` or a similar enum, add a `RecursiveStruct` variant. Otherwise, construct the diagnostic directly.

**Edge cases:**
- Direct self-reference: `struct A { self_ref: A }` — cycle of length 1.
- Transitive cycle: `struct A { b: B }`, `struct B { a: A }` — cycle of length 2.
- Multiple cycles: Report each cycle independently.
- Struct containing a class field that contains itself: NOT a cycle (class is heap-indirected).
- Struct containing an Option/Array of itself: NOT a cycle (Option and Array are heap types).

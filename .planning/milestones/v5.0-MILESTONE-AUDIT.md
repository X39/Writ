## DIFF-01 Partial Gap Detail

**Requirement:** "Semantic highlighting distinguishes entity names, component types, dialogue speakers, and keywords with distinct token types"

**What works:** Entity names (token type 2), component types (3), type names (1), function names (5), and variables (6) all emit correct semantic tokens. `package.json` `semanticTokenScopes` maps them to distinct TextMate scopes. Four semantic token tests pass.

**What's missing:** `TOKEN_TYPE_DIALOGUE_SPEAKER` (type index 4) is defined in `queries.rs:987` with `#[allow(dead_code)]`. The token type is registered in the `SemanticTokensLegend` and mapped in `package.json:31-40`, but `collect_semantic_tokens` never emits it. Dialogue `@SpeakerName` constructs have no matching `TypedExpr` variant triggering semantic highlighting.

**Impact:** Low. Dialogue speaker names still receive TextMate grammar highlighting via `dialogue-blocks` rule in `writ.tmLanguage.json`. The semantic token gap means no semantic override, but they are visually distinguished via the grammar.

**Fix scope:** Small — add a branch in `collect_semantic_tokens` to emit token type 4 for dialogue speaker references.

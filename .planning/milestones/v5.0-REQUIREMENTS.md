# Requirements: Writ Compiler

**Defined:** 2026-03-13
**Core Value:** Correct, spec-compliant implementation at every layer — structured so each layer can be extended independently.

## v5.0 Requirements

Requirements for the LSP and DAP milestone. Each maps to roadmap phases.

### Preparation

- [x] **PREP-01**: Compiled .writil debug info contains real line/column numbers (not byte offsets) for all source spans
- [x] **PREP-02**: Parser produces useful partial ASTs from incomplete or syntactically broken source files (error recovery)
- [x] **PREP-03**: RuntimeHost trait has a `before_instruction` hook that allows debug breakpoint and stepping control
- [x] **PREP-04**: Task distinguishes DAP debug suspension from host-request suspension via a SuspendReason discriminant
- [x] **PREP-05**: Compiled .writil includes debug local variable info (register index → variable name + type) per function

### Language Server

- [x] **LSP-01**: Language server publishes diagnostics (errors and warnings) as inline editor squiggles on file save or change
- [x] **LSP-02**: User gets keyword and type name completions when typing identifiers
- [x] **LSP-03**: User gets dot-completions for struct/class fields, methods, and entity components
- [x] **LSP-04**: User can hover any identifier to see its type, signature, or definition info
- [x] **LSP-05**: User can go-to-definition on any identifier to jump to its declaration
- [x] **LSP-06**: User can find all references of a definition across all files in the project
- [x] **LSP-07**: User sees signature help with active parameter highlighted during function/method calls
- [x] **LSP-08**: All LSP features work across multiple files in a writ.toml project (cross-file resolution)

### Debug Adapter

- [x] **DAP-01**: User can launch a Writ program in the VS Code debugger via F5 with a launch.json configuration
- [x] **DAP-02**: User can set source-level breakpoints on .writ file lines and execution pauses there
- [x] **DAP-03**: User can step over, step into, and step out of function calls at source level
- [x] **DAP-04**: User can inspect local variable names and values when execution is paused
- [x] **DAP-05**: User can see the full call stack with source locations when execution is paused
- [x] **DAP-06**: User can evaluate watch expressions against the current stack frame
- [x] **DAP-07**: DAP shows all Writ cooperative tasks as separate debugger threads

### VS Code Extension

- [x] **EXT-01**: VS Code extension provides TextMate syntax highlighting for .writ files
- [x] **EXT-02**: Extension registers .writ file association and activates automatically on opening .writ files
- [x] **EXT-03**: Extension bundles and launches writ-lsp and writ-dap server binaries
- [x] **EXT-04**: Extension provides default launch.json configuration snippet for Writ debugging

### Differentiators

- [x] **DIFF-01**: Semantic highlighting distinguishes entity names, component types, dialogue speakers, and keywords with distinct token types
- [x] **DIFF-02**: Dot-completion on entity-typed expressions shows available extern component types

## v6+ Requirements

### LSP Polish

- **LSPX-02**: Inlay hints showing inferred types on let bindings

### DAP Advanced

### Tooling

- **TOOLX-03**: Incremental compilation (salsa-style query graph)

## Out of Scope

| Feature | Reason |
|---------|--------|
| Rename symbol | Depends on find references being battle-tested first; ship in v5.x after validation |
| Formatter (`writ fmt`) | Requires trivia-preserving AST; current AST strips comments and whitespace |
| Incremental compilation (salsa) | Multi-milestone effort; coarse-grained file-level caching sufficient for v5.0 |
| DAP variable mutation | Mutating VM registers from outside violates type invariants; unsafe without validation pass |
| Language server as WASM | Standard pattern is native binary over stdio; WASM adds complexity without benefit |
| Real-time per-keystroke type checking | Use debounced (300ms idle) diagnostics instead; full pipeline is O(n) per file |

<objective>
Make the compiler pipeline tolerate error nodes per-function instead of aborting the entire compilation.

Purpose: The LSP (Phase 53) needs to produce diagnostics and completions for valid functions even when other functions in the same file have syntax errors. Currently, `emit_bodies` aborts entirely if any error node exists anywhere in the TypedAst. This must become function-granular: skip the broken function body, emit a diagnostic, and continue compiling the rest.

Output: Compiler that emits bodies for all valid functions even when some functions contain error nodes; diagnostic output for each skipped function.

Note: This plan depends on Plan 52-01 because both modify `writ-compiler/src/emit/mod.rs` (the `emit_bodies` function). Plan 52-01 adds a `sources` parameter; this plan removes the error pre-pass from the same function. Execute after 52-01 completes.
</objective>

  <action>
    **Step 1 — Remove file-level abort in emit_bodies (emit/mod.rs):**

    In `writ-compiler/src/emit/mod.rs`, remove or comment out the error pre-pass block (lines ~76-85):
    ```rust
    // REMOVE THIS BLOCK:
    if body::has_error_nodes(typed_ast) {
        diags.push(
            writ_diagnostics::Diagnostic::error("E9000", "Codegen aborted: TypedAst contains error nodes").build()
        );
        return Err(diags);
    }
    ```

    After removing the pre-pass, `emit_bodies` will proceed to metadata collection and body emission even when error nodes exist. The per-function skip in `emit_all_bodies` (Step 2) will handle individual broken functions.

    Also update the error handling after `emit_all_bodies` — currently, if `diags` is non-empty after body emission, it returns `Err(diags)`. Change this to only return `Err` if there are ZERO valid bodies AND there are diagnostics (meaning nothing could be compiled). If at least one body was emitted, continue to serialization with the warning diagnostics. The LSP needs partial results, not all-or-nothing.

    **Step 2 — Per-function error skip in emit_all_bodies (emit/body/mod.rs):**

    In `writ-compiler/src/emit/body/mod.rs`, in `emit_all_bodies`:
    - Remove any file-level `has_error_nodes` check at the top of the function
    - At each function/method body emission site (the match arms for `TypedDecl::Fn`, `TypedDecl::Impl` methods, etc.):
      - Before emitting the body, check if the body expression contains error nodes using the existing `expr_has_error` helper (or a wrapper that checks the full body)
      - If the body has error nodes: push a diagnostic with code `"E9001"` and a message like `"Skipping function '{name}' due to syntax errors in body"`, then `continue` to the next declaration
      - If the body is clean: proceed with normal emission

    The key insight from the research: use `continue` not `return` — so that other functions in the same file still get their bodies emitted.

    For `TypedDecl::Impl` blocks that contain multiple methods, apply the check per-method, not per-impl-block. A single broken method should not skip the entire impl.

    **Step 3 — Handle has_error_nodes utility:**

    The `has_error_nodes` function (line 184) can remain as a utility for other uses, but it should no longer be called as a file-level gate. If it is only used for the file-level abort, consider marking it `#[allow(dead_code)]` or removing it. Check all call sites.

Call `emit_all_bodies`. Assert that `bodies.len() == 1` (only the valid function) and `diags` contains a diagnostic for the skipped function.

    Test 3: Both functions have errors. Assert `bodies.len() == 0` and `diags.len() == 2`.

    Note: Constructing TypedAst programmatically requires understanding the TypedDecl/TypedExpr types. Use the simplest possible bodies — a single `TypedExpr::IntLit` for valid, and `TypedExpr::Error` for invalid.

### Gap Not Addressed: Compiler Resolution Failures on Complex Code

The REVER.md test 8 reported "resolution failed" for complex writ programs (structs, entities, cross-references). The 62-03 plan's debug_host fix only addresses log routing. The root cause — compiler name resolution failures on complex patterns in `writ-compiler/src/resolve/` — is a pre-existing compiler bug explicitly noted as out of scope for this phase.

**Impact:** Debugger will work on simple writ programs but fail on complex code with "resolution failed". This is not a gap introduced by this phase; it is a known pre-existing limitation.

### Human Verification Required

#### 1. Hover Types in Multi-File Project

**Test:** Open a writ.toml project in VS Code. In a file with `let x: MyStruct = ...`, hover over the variable name `x`.
**Expected:** Tooltip shows the correct type (`x: MyStruct`), not void, not a type from another file, not the function body return type.
**Why human:** File-ID filtering is implemented but re-verification (REVER test 3) showed a span-domain issue where let bindings showed the body return type. The `binding_at_offset` function now filters by file_id — whether it also correctly handles the Let.name_span check requires end-to-end validation.

#### 2. Go-to-Definition on Type Annotation

**Test:** In a writ.toml project file with namespace, write `let x: MyStruct = ...`. Ctrl+click on `MyStruct`.
**Expected:** Editor navigates to the struct declaration site.
**Why human:** Namespace FQN lookup is implemented; however re-verification found complex patterns cause "resolution failed." Needs fresh test with simple struct in namespaced project.

#### 3. Find References from Declaration Site

**Test:** Place cursor on a struct or entity name at its declaration (e.g., `struct Foo` — cursor on `Foo`). Press Shift+F12.
**Expected:** References panel shows all usage sites including the declaration.
**Why human:** `def_at_offset` now filters by file_id. Re-verification showed this failed for non-function types. Needs human confirmation that the fix is sufficient.

#### 4. Breakpoints Hit in VS Code Debugger

**Test:** Open a .writ file, set a breakpoint on a line inside a function, create a launch.json with `"type": "writ"`, press F5.
**Expected:** Execution pauses at the breakpoint line with yellow highlight in VS Code.
**Why human:** byte_pc translation is in code. This is the most critical fix (UAT blocker). Requires a full VS Code + writ-dap session to confirm the coordinate fix resolves the match.

#### 5. Log Output in Debug Console

**Test:** Write a writ program with `log::info("hello")`. Run under F5 debugger.
**Expected:** `[INFO] hello` appears in the VS Code Debug Console panel.
**Why human:** DebugHost routing and Event::Output drain are in code. Requires a running DAP session to verify the output event reaches the console.

#### 6. Top-Level Expression Diagnostics

**Test:** Open a .writ file. Type `asd asd` at the top level (outside any function). Wait 1-2 seconds.
**Expected:** Red squiggle appears under the expression and Problems panel shows "expression statements are not allowed at the top level."
**Why human:** Post-parse validation is in parser.rs. Requires an active LSP session in VS Code to confirm the diagnostic propagates through the compile pipeline to the LSP diagnostics handler.

#### 7. Entity vs Struct Color Distinction

**Test:** Open a .writ file with both `struct Foo {}` and `entity Bar {}`. Observe the colors of `Foo` and `Bar` identifiers.
**Expected:** `Bar` (entity) appears in teal (#4EC9B0), `Foo` (struct/type) appears in blue (#4FC1FF). Both `struct` and `entity` keywords are highlighted. `class` keyword is also highlighted.
**Why human:** semanticTokenScopes and configurationDefaults are set in package.json. Color rendering depends on VS Code theme behavior and the extension being reinstalled/reloaded with the new package.json.

### Gaps Summary

No code-level gaps were found. All 8 truths are implemented in the codebase. The phase delivered:

1. **62-01:** File-ID filtering on all 4 LSP query functions + namespace-aware type annotation DefId lookup. This addresses the multi-file span-domain mismatch that caused hover, goto-def, and find-refs to return results from wrong files.

2. **62-02:** byte_offsets stored on LoadedModule + byte_pc translation in execute_one. This fixes the DAP breakpoint PC coordinate mismatch (instruction index vs byte offset) that prevented breakpoints from ever being hit.

3. **62-03:** DAP log routing in DebugHost + post-parse top-level expression validation + VS Code color polish (type color rule, class keyword, type semanticTokenScope). Three independent fixes.

The one known limitation is that the compiler's name resolution fails on complex writ programs (the "resolution failed" error in debugger test 8). This is a pre-existing bug not introduced by this phase and not part of this phase's scope.

Seven items require human confirmation in VS Code since they involve visual rendering, debugger sessions, and LSP client behavior that cannot be verified programmatically.

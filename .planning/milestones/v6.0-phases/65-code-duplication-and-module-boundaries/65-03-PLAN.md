**Strategy:** Use `cargo check` as the oracle. The approach is iterative:

1. **Identify candidates:** In `writ-compiler`, the `check/`, `emit/`, and `lower/` submodules have many `pub fn` and `pub struct` items. Items that are ONLY used within writ-compiler (not by integration tests in `writ-compiler/tests/` or by external crates like writ-lsp) can be `pub(crate)`.

2. **Safe narrowing procedure per module:**
   a. Pick a target file (e.g., `writ-compiler/src/check/env.rs`)
   b. Change `pub fn` / `pub struct` to `pub(crate) fn` / `pub(crate) struct` for items NOT listed in the crate's `lib.rs` re-exports
   c. Run `cargo check --workspace`
   d. If errors mention the item in `writ-compiler/tests/` or another crate, revert that specific item back to `pub`
   e. Repeat for each item

3. **Priority targets for narrowing** (items likely internal-only based on module structure):
   - `writ-compiler/src/lower/fmt_string.rs`: `lower_fmt_string` — currently `pub`, but only called from within `lower/` (dialogue.rs and expr.rs). Change to `pub(crate)` if no external access. Actually, since dialogue.rs imports it as `use crate::lower::fmt_string::lower_fmt_string`, `pub(crate)` suffices.
   - `writ-compiler/src/lower/context.rs`: Check if `LoweringContext` methods are used externally (it IS re-exported in lib.rs, so the struct stays `pub`, but internal helper methods may be narrowable)
   - `writ-compiler/src/check/` submodule functions: `type_check`, `check_decl`, `check_expr`, `check_stmt` — check which are accessed externally
   - `writ-compiler/src/emit/` submodule functions and types in `metadata.rs`, `body/*.rs`

4. **DO NOT narrow items that:**
   - Are listed in `writ-compiler/src/lib.rs` re-exports (`Ast`, `lower`, `LoweringError`, `LoweringContext`, `emit_bodies`)
   - Are accessed by `writ-compiler/tests/*.rs` integration tests
   - Are accessed by `writ-lsp` (which imports from `writ_compiler::*`)

5. **For non-writ-compiler crates:** Quickly check `writ-runtime`, `writ-module`, `writ-assembler` for obvious candidates. These crates already use `pub(crate)` in some places (writ-module has `pub(crate) mod reader` and `pub(crate) mod writer`). Run `cargo check` after any narrowing.

6. **Important:** This is a best-effort pass. The goal is to demonstrate the review was done and narrow the most obvious candidates. Do not attempt to narrow every single `pub` item — focus on the highest-impact cases (items clearly internal to a module that leaked `pub` during file splits in phases 63-64).

**Concrete example of the change pattern:**
```rust
// BEFORE (in writ-compiler/src/lower/fmt_string.rs)
pub fn lower_fmt_string(...)

// AFTER
pub(crate) fn lower_fmt_string(...)
```

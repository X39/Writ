## Phase Details

### Phase 70: Docker Environment and Measurement Harness
**Goal**: Users can run `docker build` and get a single image with all 6 language runtimes at pinned versions, a validated hyperfine-based timing harness, and a stub `raw.json` proving the measurement pipeline works end-to-end
**Depends on**: Nothing (first phase of v7.0)
**Requirements**: INFRA-01, INFRA-02, INFRA-03, INFRA-04, INFRA-05, INFRA-06, INFRA-07, INFRA-08
**Success Criteria** (what must be TRUE):
  1. `docker build -t writ-bench -f benchmark/runner/Dockerfile .` completes without error and includes Writ, Lua 5.4, Squirrel 3.x, Python 3.x, Node.js 22 LTS, and a pre-compiled Rust binary
  2. `run.sh` (Linux/macOS) and `run.ps1` (Windows) each launch the container and produce `benchmark/results/raw.json` using only Docker/Podman as an external prerequisite
  3. A stub benchmark produces a `raw.json` where Writ results are split into `writ_compile` and `writ_run` objects (each containing median, mad, memory_kb), and each other language has its own result object (lua, squirrel, python, node, rust) with the same fields
  4. The harness reports median execution time and MAD over N runs, peak anonymous RSS memory usage, and startup time as distinct JSON fields
  5. Container startup emits pinned version strings for all 6 runtimes, confirming the correct versions are present
**Plans:** 1/1 plans complete
Plans:
- [x] 70-01-PLAN.md — Dockerfile + stub benchmark files (INFRA-01)
- [x] 70-02-PLAN.md — Measurement harness bench_runner.sh (INFRA-04, INFRA-05, INFRA-06, INFRA-07, INFRA-08)
- [x] 70-03-PLAN.md — Host runner scripts run.sh + run.ps1 (INFRA-02, INFRA-03)
- [ ] 70-04-PLAN.md — Gap closure: run Docker pipeline end-to-end, validate raw.json (SC1-SC5)

### Phase 71: Compute Benchmarks MVP
**Goal**: Users can run the full benchmark pipeline against the two compute benchmarks (Fibonacci and prime sieve) across all 6 languages, observe matching output checksums confirming algorithmic equivalence, and see a populated `raw.json` with correct timing and Writ compile/run separation
**Depends on**: Phase 70
**Requirements**: BENCH-01, BENCH-02, BENCH-08
**Success Criteria** (what must be TRUE):
  1. `benchmark/cases/fib/` contains six source files (fib.writ, fib.lua, fib.nut, fib.py, fib.js, fib.rs) all computing fib(40) and printing the same result
  2. `benchmark/cases/sieve/` contains six source files all computing the Eratosthenes sieve to N=1,000,000 and printing the same prime count
  3. `raw.json` contains entries for both benchmarks with N >= 30 timing samples, median + MAD statistics, and Writ's `compile_ms` separated from `run_ms`
  4. Running `writ compile` then `writ run` on each `.writ` benchmark file succeeds without errors on the current build
**Plans:** 2 plans
Plans:
- [ ] 71-01-PLAN.md — Fibonacci benchmark: all 6 language implementations (BENCH-01, BENCH-08)
- [ ] 71-02-PLAN.md — Array .push()/.len() compiler support + Eratosthenes sieve benchmark (BENCH-02, BENCH-08)

### Phase 72: Chart Generation and Results Pipeline
**Goal**: Users can run one command from the repo root and get dated SVG bar charts and a markdown results table committed under `benchmark/results/YYYY-MM-DD/`, regenerable from any historical `raw.json`
**Depends on**: Phase 71
**Requirements**: REPORT-01, REPORT-02, REPORT-03, REPORT-04, REPORT-05
**Success Criteria** (what must be TRUE):
  1. `generate.py` reads `raw.json` and produces per-benchmark SVG bar charts for execution time (log scale, Y-axis anchored at 0, units labeled) plus a linear-scale chart for interpreted-languages-only comparison
  2. `generate.py` produces a second SVG chart for memory usage comparison and a third for startup time comparison
  3. `generate.py` produces `RESULTS.md` containing a markdown table with language, median_ms, memory_mb, compile_ms (Writ only), and ratio-to-Rust columns
  4. All output files land in `benchmark/results/YYYY-MM-DD/` and are committed to the repository
  5. Deleting and re-running `generate.py` against the same `raw.json` produces bit-identical SVG and markdown output
**Plans:** 2 plans
Plans:
- [ ] 72-01-PLAN.md — generate.py: SVG chart generation + RESULTS.md table (REPORT-01, REPORT-02, REPORT-03, REPORT-04)
- [ ] 72-02-PLAN.md — Host runner integration + end-to-end validation (REPORT-05)

**Depends on**: Phase 72
**Requirements**: BENCH-03, BENCH-04, BENCH-05, BENCH-06, BENCH-07
**Success Criteria** (what must be TRUE):
  1. `benchmark/cases/string_concat/` contains six source files all running an equivalent string concatenation loop and producing matching output
  2. `benchmark/cases/array_sort/` and `benchmark/cases/hash_map/` each contain six equivalent implementations with verified matching output
  3. `benchmark/cases/oop_dispatch/` and `benchmark/cases/object_create/` each contain six implementations allocating the same object count with verified matching output
  4. `raw.json` is extended with all five new benchmark suites and `generate.py` produces updated charts and `RESULTS.md` covering all seven benchmarks

**Step 2: Run the pipeline with minimal iterations**

From the repo root (`D:/dev/git/Writ`), execute:
```bash
cd D:/dev/git/Writ && RUNS=3 ./benchmark/runner/run.sh
```

This will:
1. Build the Docker image (`docker build -t writ-bench -f benchmark/runner/Dockerfile .`)
2. Run the container with volume mount to `benchmark/results/YYYY-MM-DD/`
3. bench_runner.sh inside the container will:
   - Emit version strings for all 6 runtimes
   - Run hyperfine timing for each language on the stub benchmark
   - Measure memory via /proc/pid/status
   - Measure startup times
   - Assemble and write raw.json

Use `RUNS=3` (not the default 10) to minimize execution time while still producing valid statistics.

**Step 3: If the Docker build fails, diagnose and fix**

Common failure modes and remediation:

a) **`cargo build --release --bin writ` fails in Stage 1:**
   - Check Cargo.toml exists at repo root and lists `writ-cli` in workspace members
   - Check that all COPY directives match actual crate directories
   - If a new crate was added since Plan 01 but not listed in the Dockerfile COPY lines, add it
   - Fix the Dockerfile and re-run

b) **NodeSource GPG key download fails (network issue):**
   - The GPG key URL is `https://deb.nodesource.com/gpgkey/nodesource-repo.gpg.key`
   - If this fails, check network/proxy settings in Docker Desktop
   - Retry; if persistent, consider using the alternative install method: `curl -fsSL https://deb.nodesource.com/setup_22.x | bash -`

c) **Squirrel git clone fails:**
   - The URL is `https://github.com/albertodemichelis/squirrel.git` at tag `v3.2`
   - If GitHub is unreachable, retry
   - If tag v3.2 doesn't exist (unlikely), check the repo for the correct tag name

d) **hyperfine .deb download fails:**
   - URL: `https://github.com/sharkdp/hyperfine/releases/download/v1.20.0/hyperfine_1.20.0_amd64.deb`
   - If 404, check https://github.com/sharkdp/hyperfine/releases for current version and update the Dockerfile

e) **`apt-get purge` breaks dependencies (cmake/build-essential/git removal):**
   - If `sq`, `python3`, or other binaries break after purge, remove the purge step from the Dockerfile
   - The purge step is optional (image size optimization only)

f) **bench_runner.sh fails at runtime:**
   - Check container logs carefully for which language/step fails
   - Common: `writ compile` may fail if the writ binary wasn't copied correctly
   - Common: `sq` may not be in PATH if the COPY from source build used wrong path
   - Fix the specific issue in the relevant file and re-run

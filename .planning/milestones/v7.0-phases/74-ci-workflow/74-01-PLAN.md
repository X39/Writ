  <action>
Create `.github/workflows/benchmark.yml` with the following exact structure:

**Name:** `Benchmarks`

**Triggers (per locked decisions):**
- `workflow_dispatch` with a single input `runs` of type `string`, description `'Benchmark iterations (default: 10)'`, required `false`, default `'10'`
- `schedule` with cron `'0 6 * * 1'` (Monday 06:00 UTC)

**Concurrency guard (Claude's discretion -- add for safety):**
```yaml
concurrency:
  group: benchmark-${{ github.ref }}
  cancel-in-progress: false
```
This prevents two benchmark runs from executing simultaneously. `cancel-in-progress: false` means a second run waits rather than canceling the in-flight one (safer for benchmarks).

**Single job:** `benchmark` on `runs-on: ubuntu-latest`

**Steps in exact order:**

1. **Checkout** -- `uses: actions/checkout@v4`

2. **Set date and results directory** -- `run:` block that writes two env vars to `$GITHUB_ENV`:
   ```bash
   echo "DATE=$(date +%Y-%m-%d)" >> $GITHUB_ENV
   echo "RESULTS_DIR=$GITHUB_WORKSPACE/benchmark/results/$(date +%Y-%m-%d)" >> $GITHUB_ENV
   ```

3. **Create results directory** -- `run: mkdir -p "${{ env.RESULTS_DIR }}"`

4. **Build benchmark image** -- `run: docker build -t writ-bench -f benchmark/runner/Dockerfile .`
   (No `working-directory:` -- Docker build context MUST be repo root, which is the default `$GITHUB_WORKSPACE` after checkout)

5. **Run benchmarks** -- `run:` block:
   ```bash
   docker run --rm \
     -v "${{ env.RESULTS_DIR }}:/results" \
     -e RESULTS_DIR=/results \
     -e RUNS=${{ inputs.runs || 10 }} \
     writ-bench
   ```
   Key: Use single `/results` (not `//results` -- that's the MINGW workaround from run.sh). Use `${{ inputs.runs || 10 }}` for the fallback when triggered by schedule (inputs.runs is empty on schedule trigger).

6. **Install pygal** -- `run: pip install pygal==3.1.0`

7. **Generate charts and RESULTS.md** -- `run: python3 benchmark/generate.py "${{ env.RESULTS_DIR }}/raw.json"`

8. **Write job summary (Claude's discretion -- high value, low effort)** -- `run:` block that appends RESULTS.md content to `$GITHUB_STEP_SUMMARY`:
   ```bash
   echo "## Benchmark Results" >> $GITHUB_STEP_SUMMARY
   echo "" >> $GITHUB_STEP_SUMMARY
   cat "${{ env.RESULTS_DIR }}/RESULTS.md" >> $GITHUB_STEP_SUMMARY
   ```

9. **Upload benchmark artifacts** -- `uses: actions/upload-artifact@v4` with:
   - `name: benchmark-results-${{ env.DATE }}`
   - `path: ${{ env.RESULTS_DIR }}/`
   (Trailing slash means upload directory contents. No retention override -- GitHub default 90 days.)

**Things NOT to do (per locked decisions and deferred ideas):**
- Do NOT call run.sh directly (contains MINGW path logic irrelevant to Linux CI)
- Do NOT use setup-python action (ubuntu-latest has python3 pre-installed)
- Do NOT commit results back to the repo (artifacts only)
- Do NOT implement regression detection (CI-04 is deferred to v7.1+)
- Do NOT add Docker layer caching for v7.0 (per RESEARCH.md recommendation -- skip for now)

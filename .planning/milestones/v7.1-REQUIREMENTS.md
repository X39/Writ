# Requirements: Writ v7.1

**Defined:** 2026-03-22
**Core Value:** Correct, spec-compliant implementation at every layer — structured so each layer can be extended independently.

## v7.1 Requirements

### Build Configuration

- [x] **BUILD-01**: Release profile uses LTO fat (`lto = "fat"`) enabling cross-crate inlining
- [x] **BUILD-02**: Release profile uses single codegen unit (`codegen-units = 1`) for maximum optimization
- [x] **BUILD-03**: Release profile uses panic=abort to eliminate unwind tables
- [x] **BUILD-04**: writ-runtime uses FxHashMap (rustc-hash) for DispatchTable and Scheduler.tasks
- [x] **BUILD-05**: Release-mode fib(40) baseline is measured and documented before any code optimization

### Inline Annotations

- [x] **INLINE-01**: All value extraction functions in helpers.rs have `#[inline(always)]` (extract_int, extract_float, extract_bool, extract_ref, extract_entity)
- [x] **INLINE-02**: All arithmetic/comparison/branch exec_* functions in arith.rs have `#[inline]`
- [x] **INLINE-03**: exec_call, exec_ret, and other frequently-hit call functions in calls.rs have `#[inline]`
- [x] **INLINE-04**: execute_one itself does NOT have `#[inline]` (prevents I-cache regression)

### Call Convention

- [x] **CALL-01**: exec_call copies arguments directly from caller registers to callee registers without intermediate Vec
- [x] **CALL-02**: exec_call_virt copies arguments directly without intermediate Vec
- [x] **CALL-03**: exec_call_indirect copies arguments directly without intermediate Vec
- [x] **CALL-04**: exec_tail_call copies arguments directly without intermediate Vec
- [x] **CALL-05**: All existing call-related tests pass after zero-allocation conversion

### Frame Management

- [x] **FRAME-01**: RegisterPool struct exists with acquire(reg_count) and release(vec) methods
- [x] **FRAME-02**: Pool acquire reuses a Vec from the free-list when capacity is sufficient
- [x] **FRAME-03**: Pool release clears Vec to Value::Void before storing in free-list
- [x] **FRAME-04**: Pool size is capped (e.g., 64 entries) to prevent unbounded memory retention
- [x] **FRAME-05**: execute_ret returns popped frame's register Vec to the pool
- [x] **FRAME-06**: Pool-correctness test verifies reused registers contain Value::Void

### Dispatch Loop

- [x] **DISPATCH-01**: execute_batch function runs multiple instructions without returning to scheduler
- [x] **DISPATCH-02**: execute_batch terminates batch on any non-Continue ExecutionResult
- [x] **DISPATCH-03**: execute_batch respects ExecutionLimit (clamps batch size to remaining limit)
- [x] **DISPATCH-04**: execute_batch falls back to single-instruction dispatch when debug hooks are enabled
- [x] **DISPATCH-05**: Frame reference is re-acquired after any stack-changing instruction (Call, Ret, TailCall)

### Value Representation

- [x] **VALUE-01**: InlineStruct fields are stored on the GC heap via HeapRef instead of inline Vec
- [x] **VALUE-02**: Value enum derives Copy (all variants are Copy-sized)
- [x] **VALUE-03**: GC collect_value_refs traces Value::Struct(HeapRef) as a heap root
- [x] **VALUE-04**: GC regression test confirms struct-in-register survives garbage collection
- [x] **VALUE-05**: Field access (exec_get_field, exec_set_field) reads/writes through HeapRef
- [x] **VALUE-06**: All existing tests pass after Value migration (cargo test --release)

### Verification

- [x] **VERIFY-01**: fib(40) produces correct output 102334155 after each phase
- [x] **VERIFY-02**: cargo test --release passes after each phase with zero failures
- [x] **VERIFY-03**: cargo build --release produces no warnings after each phase
- [x] **VERIFY-04**: fib(40) completes in under 30 seconds after all phases (release build)

## Future Requirements

### Performance (v8.0+)

- **PERF-01**: Inline caching for CALL_VIRT dispatch (OOP-heavy workload optimization)
- **PERF-02**: Superinstructions combining frequent instruction sequences
- **PERF-03**: NaN-boxing / tagged-pointer Value representation
- **PERF-04**: Unsafe bounds-check elimination on register access
- **PERF-05**: JIT compilation

## Out of Scope

| Feature | Reason |
|---------|--------|
| JIT compilation | Explicitly out of scope per PROJECT.md; requires separate multi-month milestone |
| NaN-boxing | Complete rewrite of value.rs and all handlers; EntityId doesn't fit NaN encoding |
| Computed goto dispatch | Requires nightly asm!; match already compiles to jump table with LTO |
| Multithreaded execution | Cooperative model is spec-defined; threading would violate spec |
| Instruction set changes | Constraint: do not change instruction set or compiler output |
| Public API changes | Constraint: do not change public API signatures beyond necessity |

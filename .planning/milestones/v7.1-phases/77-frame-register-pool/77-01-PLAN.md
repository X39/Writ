    - After 70 releases, free_list.len() never exceeds 64
    - After release, the pooled Vec has len=0 but capacity preserved

  </behavior>
  <action>
    Add RegisterPool to writ-runtime/src/frame.rs BELOW the existing CallFrame impl block.

    1. Add constant: `const POOL_CAP: usize = 64;`

    2. Add struct:
    ```rust
    pub struct RegisterPool {
        free_list: Vec<Vec<Value>>,
    }
    ```

    3. Implement:
    - `pub fn new() -> Self` — empty free_list
    - `#[inline] pub fn acquire(&mut self, reg_count: usize) -> Vec<Value>` — scan free_list from back (rev), find first with capacity >= reg_count, swap_remove it, resize to reg_count filling with Value::Void. If no match, allocate `vec![Value::Void; reg_count]`.
    - `#[inline] pub fn release(&mut self, mut v: Vec<Value>)` — if free_list.len() >= POOL_CAP, drop v (return early). Otherwise: `v.fill(Value::Void)` then `v.clear()` then push to free_list. The fill-then-clear sequence ensures memory is cleaned (FRAME-03) while clear() preserves capacity.
    - `impl Default for RegisterPool` delegating to new()

    4. Add `CallFrame::with_pool` constructor:
    ```rust
    pub fn with_pool(pool: &mut RegisterPool, method_idx: usize, reg_count: usize, return_register: u16) -> Self {
        Self {
            method_idx,
            pc: 0,
            registers: pool.acquire(reg_count),
            defer_stack: Vec::new(),
            return_register,
        }
    }
    ```

    5. Update writ-runtime/src/lib.rs to also re-export RegisterPool:
    Add `pub use frame::RegisterPool;` next to the existing `pub use frame::CallFrame;` line.

    IMPORTANT: Do NOT modify or remove CallFrame::new — it remains for backward compatibility.

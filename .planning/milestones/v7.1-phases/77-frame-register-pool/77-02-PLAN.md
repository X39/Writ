    **Step 1: scheduler.rs — Add pool field to Scheduler**

    - Add field `pub(crate) pool: RegisterPool` to Scheduler struct
    - Initialize with `pool: RegisterPool::new()` in Scheduler::new()
    - In create_task: change `CallFrame::new(method_idx, reg_count, 0)` to `CallFrame::with_pool(&mut self.pool, method_idx, reg_count, 0)`

    **Step 2: scheduler.rs — Thread pool to execute_one**
    - In run_one_task, the `execute_one(...)` call site (around line 106): add `&mut self.pool` as the last argument. The existing pattern of `&mut self.globals` and `&mut self.entity_registry` shows field split-borrows work here.

    **Step 3: scheduler.rs — Thread pool to execute_crash**
    - There are TWO execute_crash call sites in scheduler.rs (around lines 157 and 296). Add `&mut self.pool` as the last argument to both.

    **Step 4: dispatch/mod.rs — Add pool to ExecContext**
    - Add `use crate::frame::RegisterPool;` to imports
    - Add field `pub pool: &'a mut RegisterPool` to ExecContext struct

    **Step 5: dispatch/mod.rs — Update execute_one signature**
    - Add `pool: &mut RegisterPool` as the last parameter to execute_one
    - In the ExecContext construction inside execute_one, add `pool` field

    **Step 6: dispatch/mod.rs — Update execute_ret signature and body**
    - Add `pool: &mut RegisterPool` parameter to execute_ret (after entity_registry)
    - After `let popped = task.call_stack.pop().unwrap();` (line 534), add: `pool.release(popped.registers);`
    - IMPORTANT: `popped.registers` is moved into pool.release, so the variable `popped` must not be used for `.registers` after this. The `.return_register` field is Copy (u16) so it can still be read. Restructure: read `popped.return_register` BEFORE releasing registers, or use a let binding. Specifically:
      ```rust
      let return_register = popped.return_register;
      pool.release(popped.registers);
      // Then use return_register below instead of popped.return_register
      ```

    **Step 7: dispatch/mod.rs — Update execute_ret call sites**
    - Ret arm (line 367): add `ctx.pool` as the last argument to execute_ret. But ctx is consumed by the destructuring into individual fields. Look at how it is actually called — it passes `ctx.task`, `ctx.modules`, etc. individually. Add `ctx.pool` at the end.
    - RetVoid arm (line 372): same — add `ctx.pool`.
    - NOTE: ctx.pool is `&mut RegisterPool` but execute_ret takes `pool: &mut RegisterPool`. Since `ctx.pool` is already `&'a mut RegisterPool`, passing it as `ctx.pool` will reborrow it. This is fine.

    **Step 8: dispatch/mod.rs — Update execute_crash signature and body**
    - Add `pool: &mut RegisterPool` as the last parameter to execute_crash
    - In the frame-unwind loop (`while !task.call_stack.is_empty()`), after `let frame = task.call_stack.pop().unwrap();` (line 683 area), change the bare pop to: `let frame = task.call_stack.pop().unwrap(); pool.release(frame.registers);`
    - Note: The crash_info construction (lines 619-666) clones registers via `f.registers.clone()` BEFORE the unwind loop, so the pool release does not affect crash inspection.

    **Step 9: dispatch/mod.rs — Update execute_defer_handler signature**
    - Add `pool: &mut RegisterPool` as the last parameter
    - Thread it to the `execute_one(...)` call inside execute_defer_handler
    - Also thread pool in the two places execute_defer_handler is called:
      (a) Inside execute_ret (line 520 area) — pass `pool`
      (b) Inside execute_crash (line 671 area) — pass `pool`

    **Step 10: dispatch/calls.rs — Use CallFrame::with_pool in all call handlers**
    - In exec_call: replace `CallFrame::new(method_idx, reg_count, r_dst)` with `CallFrame::with_pool(ctx.pool, method_idx, reg_count, r_dst)`
    - In exec_call_virt (the Method arm that pushes a frame): same replacement
    - In exec_call_indirect: same replacement
    - Do NOT change exec_tail_call — it reuses the existing frame in-place via clear()+resize(), never pops/pushes.
    - Do NOT change exec_call_extern — it does not create a CallFrame.

    IMPORTANT: After all changes, run `cargo build -p writ-runtime --release` to verify compilation. Fix any borrow checker issues. The most likely issue is the ctx.pool reborrow in the Ret/RetVoid arms — if the borrow checker complains, extract `ctx.pool` via a temporary binding before the execute_ret call.

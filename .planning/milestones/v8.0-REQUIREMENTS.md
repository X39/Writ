# Requirements: Writ Compiler — Contract-as-Type

**Defined:** 2026-03-23
**Core Value:** Correct, spec-compliant implementation at every layer — lowering matches Section 28 exactly, runtime matches the IL spec exactly — structured so each layer can be extended independently.

## v8.0 Requirements

Requirements for contract-as-type support. Each maps to roadmap phases.

### Spec

- [x] **SPEC-01**: §1.11 documents that contract names can be used as types for variables, parameters, and return types
- [x] **SPEC-02**: §1.11 documents assignability: a value of type T is assignable to contract C if T implements C
- [x] **SPEC-03**: §1.11 documents that method calls on contract-typed values dispatch virtually (CALL_VIRT)

### Type System

- [x] **TYPE-01**: TyKind::Contract(DefId) variant exists in the type interner
- [x] **TYPE-02**: `def_id_to_ty` resolves DefKind::Contract to TyKind::Contract (not Error)
- [x] **TYPE-03**: Assignment from concrete type to contract type succeeds when the concrete type implements the contract
- [x] **TYPE-04**: Assignment from concrete type to contract type fails with clear error when the type does NOT implement the contract
- [x] **TYPE-05**: Method calls on contract-typed receivers resolve through contract_methods and type-check correctly

### Code Generation

- [x] **EMIT-01**: Method calls on contract-typed receivers emit CALL_VIRT (not CALL)
- [x] **EMIT-02**: CALL_VIRT carries correct contract_idx and slot for contract-typed dispatch
- [x] **EMIT-03**: E0122 (contract-as-type error) removed — contract type annotations compile successfully
- [x] **EMIT-04**: The original 5-bug repro script compiles and runs correctly (implementedFunc succeeds, notImplementedFunc caught by E0123)

### LSP

- [x] **LSP-01**: Dot-completion on contract-typed variables shows contract methods
- [x] **LSP-02**: Hover on contract-typed variables shows the contract type name
- [x] **LSP-03**: Diagnostics for contract-typed code work correctly (no false positives or missing errors)

## Future Requirements

### Contract Extensions

- **CEXT-01**: Multiple contract bounds on generic parameters (T: A + B)
- **CEXT-02**: Contract inheritance (contract B extends A)
- **CEXT-03**: Default method implementations in contracts

## Out of Scope

| Feature | Reason |
|---------|--------|
| Contract inheritance / extends | Not in current spec; future milestone |
| Default method implementations | Requires spec amendment; future milestone |
| Dynamic dispatch tables (vtables) | Current HashMap dispatch is correct; vtable optimization is a separate concern |
| Contract objects / trait objects with fat pointers | Current boxing model is sufficient; optimization later |

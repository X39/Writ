### v8.0 Contract-as-Type (Phases 83-86)

**Milestone Goal:** Enable contracts to be used as first-class types — variables, parameters, and return types can be contract-typed, with runtime virtual dispatch via CALL_VIRT.

- [x] **Phase 83: Spec Review** - Update §1.11 to document contract-as-type semantics (completed 2026-03-23)
- [x] **Phase 84: Type System** - Add TyKind::Contract, assignability, and method resolution on contract-typed receivers (completed 2026-03-23)
- [x] **Phase 85: Code Generation** - Emit CALL_VIRT for method calls on contract-typed receivers and remove E0122 (completed 2026-03-23)
- [x] **Phase 86: LSP Support** - Completions, hover, and diagnostics for contract-typed variables (completed 2026-03-24)

## Phase Details

### Phase 75: Baseline, Build Config, and Inline Annotations
**Goal**: The VM runs in a fully release-optimized configuration with a measured, documented performance baseline and inline annotations applied to hot dispatch helpers
**Depends on**: Nothing (first phase of v7.1)
**Requirements**: BUILD-01, BUILD-02, BUILD-03, BUILD-04, BUILD-05, INLINE-01, INLINE-02, INLINE-03, INLINE-04, VERIFY-01, VERIFY-02, VERIFY-03
**Success Criteria** (what must be TRUE):
  1. `cargo build --release` produces a binary with LTO, single codegen unit, and panic=abort — confirmed by `cargo bloat --release` showing no unwind tables
  2. FxHashMap is used for DispatchTable and Scheduler.tasks — confirmed by inspecting writ-runtime/Cargo.toml and the relevant type definitions
  3. fib(40) run time in release mode is measured and committed to the repo as the v7.1 pre-optimization baseline
  4. All value-extraction helpers (extract_int, extract_float, etc.) and arithmetic handlers carry the correct inline annotations; execute_one has no inline annotation
  5. `cargo test --release` passes with zero failures and `cargo build --release` produces zero warnings
**Plans:** 2/2 plans complete

Plans:
- [x] 75-01-PLAN.md — Release profile, FxHashMap substitution, and inline annotations
- [x] 75-02-PLAN.md — Baseline measurement and full verification

### Phase 76: Zero-Allocation Call Convention
**Goal**: Every call instruction copies arguments directly from caller registers to callee registers without allocating an intermediate Vec
**Depends on**: Phase 75
**Requirements**: CALL-01, CALL-02, CALL-03, CALL-04, CALL-05, VERIFY-01, VERIFY-02, VERIFY-03
**Success Criteria** (what must be TRUE):
  1. exec_call, exec_call_virt, exec_call_indirect, and exec_tail_call all pass arguments without creating a staging Vec — confirmed by absence of `Vec::with_capacity` in arg-passing paths
  2. A release-mode fib(40) run after this phase completes faster than the Phase 75 baseline, with the delta recorded
  3. All call-related tests pass, including at least one test exercising tail-call argument passing
  4. `cargo test --release` passes with zero failures and `cargo build --release` produces zero warnings
**Plans:** 2/2 plans complete

Plans:
- [x] 76-01-PLAN.md — Add missing call-instruction test coverage (tail-call multi-arg, call-indirect args)
- [x] 76-02-PLAN.md — Refactor all call handlers to zero-allocation and record performance delta

### Phase 77: Frame Register Pool
**Goal**: Deallocated register Vecs are pooled and reused on the next call, eliminating per-call register Vec allocation for the common case
**Depends on**: Phase 76
**Requirements**: FRAME-01, FRAME-02, FRAME-03, FRAME-04, FRAME-05, FRAME-06, VERIFY-01, VERIFY-02, VERIFY-03
**Success Criteria** (what must be TRUE):
  1. RegisterPool exists with acquire/release methods; pool size is capped at 64 entries; execute_ret returns the popped frame's Vec to the pool
  2. A pool-correctness test acquires a frame, writes non-Void values, releases it, re-acquires, and asserts every register is Value::Void
  3. A release-mode fib(40) run after this phase completes faster than the Phase 76 result, with the delta recorded
  4. `cargo test --release` passes with zero failures and `cargo build --release` produces zero warnings
**Plans:** 2/2 plans complete

Plans:
- [x] 77-01-PLAN.md — RegisterPool struct, pool-aware CallFrame constructor, and pool correctness tests
- [x] 77-02-PLAN.md — Thread pool through execution pipeline (Scheduler, ExecContext, execute_ret, execute_crash, call handlers) and measure fib(40) delta

### Phase 78: Inner Dispatch Loop
**Goal**: The scheduler runs multiple instructions per task slice without returning to the outer loop, eliminating the per-instruction HashMap task lookup
**Depends on**: Phase 77
**Requirements**: DISPATCH-01, DISPATCH-02, DISPATCH-03, DISPATCH-04, DISPATCH-05, VERIFY-01, VERIFY-02, VERIFY-03
**Success Criteria** (what must be TRUE):

  2. A test confirms execute_batch falls back to single-instruction dispatch when debug hooks are enabled (DAP connection path)
  3. A test confirms execute_batch does not overshoot the ExecutionLimit when one is active
  4. A release-mode fib(40) run after this phase completes faster than the Phase 77 result, with the delta recorded
  5. `cargo test --release` passes with zero failures and `cargo build --release` produces zero warnings
**Plans**: 1 plan
Plans:
- [x] 78-01-PLAN.md — execute_batch inner dispatch loop, scheduler restructure, tests, and benchmark

### Phase 79: Copy-Semantic Value Enum
**Goal**: Value derives Copy by storing InlineStruct fields on the GC heap, making register-to-register moves bitwise copies throughout all dispatch handlers
**Depends on**: Phase 78
**Requirements**: VALUE-01, VALUE-02, VALUE-03, VALUE-04, VALUE-05, VALUE-06, VERIFY-01, VERIFY-02, VERIFY-03, VERIFY-04
**Success Criteria** (what must be TRUE):
  1. Value::Struct(HeapRef) replaces Value::InlineStruct across all match sites in the workspace; Value derives Copy; no Value::InlineStruct variant exists at compile time
  2. A GC regression test places a struct value in a register, triggers garbage collection, and confirms the struct fields survive (proving collect_value_refs traces Struct(HeapRef) correctly)
  3. exec_get_field and exec_set_field read and write through HeapRef without accessing any inline Vec
  4. fib(40) completes in under 30 seconds in release mode
  5. `cargo test --release` passes with zero failures and `cargo build --release` produces zero warnings
**Plans**: 2 plans
Plans:
- [x] 79-01-PLAN.md — Value enum migration, GC regression test, runtime match sites
- [x] 79-02-PLAN.md — Full workspace verification and fib(40) performance benchmark

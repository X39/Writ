**1.28.2 `typeof(expr)` -- Static Type Query** — Explain that `typeof(expr)` is a compile-time query that returns a `Type` object representing the **static** (declared) type of the expression. The type index is baked into the IL at compile time via the `TYPEOF` opcode (see section 3.10). The result is a lazily-allocated singleton `Type` heap object -- `typeof(T) == typeof(T)` is always true (identity by TypeDef). Include this code example:

```writ
let t: Type = typeof(Player);
log($"Type name: {t.name}");         // "Player"
log($"Namespace: {t.namespace}");    // e.g., "game.entities"

for field in t.fields() {
    log($"  {field.name}: {field.declared_type.name}");
}
```

**1.28.3 `get_type()` -- Dynamic Type Query** — Explain that `get_type()` is a dynamic runtime query dispatched via the `Reflectable` contract (section 1.28.4). It returns the **runtime** actual type, which may differ from the static type for polymorphic variables. Include the divergence example:

```writ
fn inspect(a: Animal) {
    let static_t  = typeof(a);       // Always: Type for Animal (compile-time static type)
    let dynamic_t = a.get_type();    // May be: Type for Dog (runtime actual type)
    let same = static_t == dynamic_t; // false when a is a subtype
}
```

**1.28.4 Reflectable Contract** — Define `Reflectable` as a contract with a single method `fn get_type(self) -> Type`. State the auto-implementation rule: the compiler automatically generates a `Reflectable` implementation for every **user-defined** type (struct, class, entity, enum). Primitives (`int`, `float`, `bool`, `string`) use separate intrinsics (`IntGetType`, `FloatGetType`, `BoolGetType`, `StringGetType`) registered in the virtual module (section 2.18.9). Extern types do not receive Reflectable auto-impl.

```writ
contract Reflectable {
    fn get_type(self) -> Type;
}
// Auto-implemented on all user-defined types.
// For primitives, the runtime provides intrinsic dispatch.
```

**1.28.5 Type Introspection Methods** — Document `Type.fields()`, `Type.methods()`, `Type.attributes()`, `Type.contracts()`, `Type.implements(contract)`, `Type.is_generic`, `Type.type_args()`. Note that `fields()` and `methods()` return only **public** members. `attributes()` integrates with the attribute system (section 1.17) and shares its underlying data with the `ModuleAttributeView` query API. Provide a usage example:

```writ
let t = typeof(Merchant);
for field in t.fields() {
    log($"  {field.name}: {field.declared_type.name}");
}

if t.implements(typeof(Serializable)) {
    log("Merchant is serializable");
}
```

**1.28.6 Dynamic Invocation** — Document `FieldInfo.get(instance)`, `FieldInfo.set(instance, value)`, and `MethodInfo.invoke(instance, args)`.

Rules for `FieldInfo.set()`:
- If the field was declared with `let` (immutable binding), calling `set()` crashes the current task with the error message: `"Reflection write to immutable field '{field_name}'"`.
- If the field was declared with `mut`, `set()` writes the new value.
- The runtime determines immutability from the field's declaration metadata.

Rules for `MethodInfo.invoke()`:
- Invocation executes on the current task's call stack (not a separate task).
- The invoked method participates in cooperative scheduling: `defer` blocks run on frame unwind, `spawn` within the invoked method yields as expected.
- Argument count and type validation occur at the call site; mismatches crash the task.

Rules for boxing at boundaries:
- `FieldInfo.get()` returns a `Box` value. The compiler auto-inserts `UNBOX` at the call site when the result is assigned to a concrete type.
- `FieldInfo.set()` accepts a `Box` value. The compiler auto-inserts `BOX` at the call site.
- `MethodInfo.invoke()` accepts `Box[]` args and returns `Box`. Same auto-coercion applies.
- This uses the existing BOX/UNBOX IL instructions (section 3.15). No new `TyKind::Any` is introduced.

Include the code example:
```writ
let t    = typeof(Player);
let hp   = t.fields().find(fn(f) = f.name == "hp")!;
hp.set(player, 100);  // OK if hp is 'mut'
// If hp was declared 'let', task crashes: "Reflection write to immutable field 'hp'"

let greet = t.methods().find(fn(m) = m.name == "greet")!;
greet.invoke(player, []);  // args boxed automatically by compiler
```

Note on `Type.construct()`: "Dynamic type instantiation via `Type.construct()` is reserved for a future version. Attempting to call it in this version crashes the task with `UnsupportedOperation`."

**1.28.7 Generic Reflection Scope** — Document `Type.is_generic` and `Type.type_args()`. For statically-known instantiations (via `typeof`), `type_args()` returns the concrete type arguments: e.g., `typeof(Array<int>).type_args()` returns `[typeof(int)]`. For runtime-queried types (via `get_type()`), `type_args()` may return an empty array for open generic type parameters — this is a documented limitation, not a bug. Include:

```writ
let t = typeof(Array<int>);
log($"is_generic: {t.is_generic}");   // true
for arg in t.type_args() {
    log($"  arg: {arg.name}");        // "int"
}
```

**1.28.8 Scope and Limitations** — Enumerate:
- Only `pub` fields and methods are visible through reflection
- Extern declarations are not reflectable (host-provided, not script metadata)
- Access to non-pub fields via reflection is explicitly disallowed (host trust model)
- `Type.construct()` is deferred to a future version
- String-based type lookup (`Type.for_name()`) is an explicit anti-feature (serialization injection risk; host controls type resolution)

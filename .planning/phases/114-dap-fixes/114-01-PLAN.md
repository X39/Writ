    **Step 1 — Extend compile return types to include method_file_ids:**

    In `writ-dap/src/launch.rs`:

    a) Change `run_pipeline` to also build and return `Vec<Option<writ_diagnostics::FileId>>` alongside the compiled bytes. After `Module::from_bytes` is called by the caller, the method_file_ids vector is indexed in parallel to `module.method_defs`.

    The approach: After `per_file_asts` is built (line ~100-130), walk each `(FileId, Ast)` pair and collect a map of top-level `fn`/`dlg` declaration names to their `FileId`. After compilation and `Module::from_bytes`, iterate `module.method_defs`, read each method name from `module.string_heap`, look it up in the map, and produce `Vec<Option<FileId>>`. This is done in the callers (`compile_and_load` and `compile_and_load_project`), NOT inside `run_pipeline`, since `run_pipeline` returns bytes (not a Module).

    Actually, to keep it simple: do the method_file_ids construction OUTSIDE `run_pipeline`, in both `compile_and_load` and `compile_and_load_project`, after `Module::from_bytes`. This avoids changing `run_pipeline`'s signature.

    b) In `compile_and_load` (single-file): After `Module::from_bytes`, build `method_file_ids = vec![Some(FileId(0)); module.method_defs.len()]`. All methods in single-file mode come from file 0. Change return type to `Result<(Module, &'static str, Vec<Option<writ_diagnostics::FileId>>), String>`.

    c) In `compile_and_load_project` (multi-file): After `Module::from_bytes`, walk `file_sources` to build a `HashMap<String, FileId>` mapping each top-level fn/dlg name to its FileId. Use `writ_parser::parse` output is not available here (ASTs were consumed by `run_pipeline`). Instead, re-walk the `per_file_asts` — but `per_file_asts` is local to `run_pipeline`.

    Better approach: Move the name->FileId map construction into `run_pipeline` and return it alongside the bytes. Change `run_pipeline` signature to return `Result<(Vec<u8>, Vec<(String, writ_diagnostics::FileId)>), String>` where the second element is a list of (method_name, file_id) pairs extracted from `per_file_asts`.

    In `run_pipeline`, after building `per_file_asts` (line ~100-130) and before discarding the ASTs, walk each `(FileId, Ast)` and collect `Vec<(String, FileId)>` by iterating `ast.decls` and extracting the name of each `AstDecl::Fn`, `AstDecl::Dlg`, `AstDecl::Entity` (for entity methods), etc. Use the declaration name (the function/dialogue name string).

    Then in `compile_and_load_project`, after `Module::from_bytes`, iterate `module.method_defs`, read each name via `writ_module::heap::read_string(&module.string_heap, def.name)`, look it up in the returned name->FileId pairs, and build `method_file_ids: Vec<Option<FileId>>`. Change return type to `Result<(Module, Vec<(writ_diagnostics::FileId, String)>, Vec<Option<writ_diagnostics::FileId>>), String>`.

    For `compile_and_load` (single-file), the simple `vec![Some(FileId(0)); ...]` approach works since all methods are in file 0. Return as third tuple element.

    **Step 4 — Use method_file_ids in build_stack_frames:**

    In `writ-dap/src/server/inspection.rs`:
    - Remove the top-level `source_path` and `filename` variables (lines 467-476) that use `source_paths.first()`.
    - Remove the stale comment about "True per-frame source file attribution requires FileId in SourceSpan".
    - Inside the `.map(|(frame_index, (method_idx, pc))| { ... })` closure, resolve source per-frame:

    ```rust
    let frame_source = self.method_file_ids
        .get(method_idx)
        .and_then(|opt| *opt)
        .and_then(|fid| self.source_paths.iter().find(|(id, _)| *id == fid))
        .or_else(|| self.source_paths.first())
        .map(|(_, p)| p.as_str())
        .unwrap_or("");
    let frame_filename = std::path::Path::new(frame_source)
        .file_name()
        .and_then(|n| n.to_str())
        .unwrap_or(frame_source);
    ```

    Then use `frame_source` and `frame_filename` in the `types::Source { path, name }` construction below.

    - `AstDecl::Dlg { name, .. }` — dialogue function
    - `AstDecl::Entity { name, methods, .. }` — entity with inherent methods (each method name must also be collected)
    - `AstDecl::Impl { methods, .. }` — impl block methods

    Check the actual `AstDecl` enum variants in `writ-compiler/src/lower/mod.rs` or the AST definition to get the correct field names.

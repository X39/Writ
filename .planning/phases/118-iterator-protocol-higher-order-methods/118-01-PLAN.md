1. **ListIterator<T>** cursor class:
```writ
pub class ListIterator<T> {
    source: T[],
    index: int
}

impl<T> ListIterator<T> {
    pub fn next(mut self) -> T? {
        if self.index >= self.source.len() {
            return null;
        }
        let item: T = self.source[self.index];
        self.index = self.index + 1;
        item
    }
}

impl<T> Iterator<T> for ListIterator<T> {
    pub fn next(mut self) -> T? {
        if self.index >= self.source.len() {
            return null;
        }
        let item: T = self.source[self.index];
        self.index = self.index + 1;
        item
    }
}
```
NOTE: The `impl<T> Iterator<T> for ListIterator<T>` block is the contract impl that registers the vtable slot. The inherent `impl<T> ListIterator<T>` block provides the direct method. Both are needed because CALL_VIRT dispatches through the contract impl vtable, while direct calls go through the inherent impl.

Add map/filter/reduce methods to the existing `impl<T> List<T>` block in collections.writ. Add AFTER the existing `has` method:

```writ
    pub fn map(self, f: fn(T) -> T) -> List<T> {
        let result: List<T> = new List<T> { items: [] };
        let mut i: int = 0;
        while i < self.items.len() {
            result.add(f(self.items[i]));
            i = i + 1;
        }
        result
    }

    pub fn filter(self, f: fn(T) -> bool) -> List<T> {
        let result: List<T> = new List<T> { items: [] };
        let mut i: int = 0;
        while i < self.items.len() {
            if f(self.items[i]) {
                result.add(self.items[i]);
            }
            i = i + 1;
        }
        result
    }

    pub fn reduce(self, initial: T, f: fn(T, T) -> T) -> T {
        let mut acc: T = initial;
        let mut i: int = 0;
        while i < self.items.len() {
            acc = f(acc, self.items[i]);
            i = i + 1;
        }
        acc
    }
```

NOTE on generics: The RESEARCH.md Pitfall 4 warns that `map<U>` with a second generic param may fail due to wildcard unification. The COLL-04 success criterion uses `list.map(fn(x: int) -> int { x * 2 })` where T=U=int (monomorphic). So `map` is typed as `fn(T) -> T` (homomorphic) to avoid the second generic param issue. Same for `reduce` — uses `fn(T, T) -> T` instead of `fn(U, T) -> U`. This satisfies the COLL-04 requirement while staying within Phase 117's generic wildcard constraints.

impl<T> List<T> {
    pub fn add(mut self, item: T) {
        self.items.add(item);
    }

    pub fn get(self, index: int) -> T {
        self.items[index]
    }

        let result: List<T> = new List<T> { items: [] };
        let mut i: int = 0;

            result.add(f(self.items[i]));
            i = i + 1;
        }
        result
    }
}

<objective>
Create the writ-lsp crate with diagnostic conversion utilities and the AnalysisHost that wraps the compiler pipeline to produce LSP-compatible diagnostics.

Purpose: This plan builds the core data and logic layer of the language server -- the part that takes Writ source code, runs it through parse/lower/resolve/typecheck stages, and produces structured LSP diagnostics. Without this, the tower-lsp backend (Plan 03) has nothing to call.

Output: A compilable writ-lsp crate with convert.rs (span/severity/diagnostic mapping), analysis_host.rs (standalone and project-mode analysis), and unit tests proving correctness.
</objective>

3. Implement `AnalysisHost::analyze_standalone(source: String, display_path: String) -> AnalysisResult`:
   - Assign FileId(0)
   - Box::leak the source for &'static str (consistent with run_pipeline pattern)
   - Stage 1: Parse via `writ_parser::parse(src)`. Convert parse_errs to Diagnostics via `convert::parse_error_to_diag`. If cst_opt is None, return early with parse diagnostics only.
   - Stage 2: Lower via `writ_compiler::lower(cst)`. Convert LoweringErrors via `.to_diagnostic(file_id)`.
   - Stage 3: Resolve via `writ_compiler::resolve::resolve(&asts_refs, &path_refs)`. Run even if lower had errors. Collect diagnostics.
   - Stage 4: Typecheck via `writ_compiler::check::typecheck(resolved, &asts_refs)`. Run even if resolve had errors. Collect diagnostics.
   - Skip emit stage (LSP needs diagnostics, not .writil bytes).
   - Cascade strategy (per CONTEXT.md Claude's discretion): continue through all stages regardless of earlier errors. If resolve or typecheck panics on error nodes, wrap in `std::panic::catch_unwind` and log but don't crash.
   - Return AnalysisResult with all collected diagnostics and the source text.

4. Implement `AnalysisHost::analyze_project(project_root: &Path, trigger_file: Option<&str>) -> AnalysisResult`:
   - Call `writ_compiler::config::load_config(project_root)`.
   - On `ConfigError::MissingToml`: if trigger_file is Some, fall back to analyze_standalone with that file's content read from disk. If None, return empty result.
   - On success: call `writ_compiler::config::discover_source_files(project_root, &config)`.
   - For each discovered .writ file: read contents, assign sequential FileId(0), FileId(1), etc., Box::leak each source.
   - Run full pipeline on all files together (multi-file slice to resolve and typecheck).
   - Stage 1+2: Parse and lower each file individually, accumulating asts and diagnostics.
   - Stage 3: Resolve all files together via `resolve::resolve(&asts_refs, &path_refs)`.
   - Stage 4: Typecheck together via `check::typecheck(resolved, &asts_refs)`.
   - Return AnalysisResult with diagnostics from all stages and all file_sources.

5. Write unit tests in a `#[cfg(test)] mod tests` block:

   - `test_analyze_standalone_type_error`: pass type-incorrect code (e.g. `fn main() { let x: int = true; }`), assert at least one error diagnostic
   - `test_analyze_standalone_cascade`: pass source with BOTH parse-recoverable and type errors, verify diagnostics from multiple stages appear
   - `test_analyze_project_missing_toml`: call with a temp dir that has no writ.toml, verify it doesn't panic

Note on `std::panic::catch_unwind`: The resolve and typecheck stages may panic when processing ASTs with error nodes from partial parse recovery. Wrap the resolve and typecheck calls in `catch_unwind` to prevent a single malformed file from crashing the language server. If a panic occurs, add an internal diagnostic noting the stage that panicked.

**Backend struct:**
```rust
use dashmap::DashMap;
use tower_lsp::{Client, LanguageServer, jsonrpc};
use lsp_types::*;
use url::Url;
use std::path::PathBuf;

pub struct Backend {
    pub(crate) client: Client,
    /// URI string -> source text. Updated on did_open/did_change.
    pub(crate) document_map: DashMap<String, String>,
    /// Workspace root path, set during initialize.
    pub(crate) workspace_root: tokio::sync::RwLock<Option<PathBuf>>,
}
```

**LanguageServer impl:**

`initialize`:
- Extract workspace root from `params.workspace_folders[0].uri` (preferred) or `params.root_uri` (fallback). Convert URI to filesystem path. Store in `self.workspace_root`.
- Return `InitializeResult` with capabilities:
  - text_document_sync: TextDocumentSyncOptions with open_close: true, change: TextDocumentSyncKind::FULL, save: SaveOptions { include_text: Some(true) }
  - No other capabilities yet (completions, hover, etc. are Phase 54)

`shutdown`: Return Ok(()).

`did_open`:
- Insert `params.text_document.uri.to_string() -> params.text_document.text` into document_map.
- Call `self.publish_diagnostics_for(params.text_document.uri).await`.

`did_change`:
- Update document_map with the last content_change (FULL sync mode).
- Optionally trigger re-analysis here too (or defer to did_save). Per CONTEXT.md (Claude's discretion on debounce): publish diagnostics on did_change as well for live feedback. Debounce is not strictly needed since we use spawn_blocking and the next analysis will just queue.

`did_save`:
- If params includes text, update document_map.
- Call `self.publish_diagnostics_for(params.text_document.uri).await`.

`did_close`:
- Remove URI from document_map.
- Publish empty diagnostics to clear squiggles: `client.publish_diagnostics(uri, vec![], None).await`.

**publish_diagnostics_for method:**

```rust
impl Backend {
    async fn publish_diagnostics_for(&self, uri: Url) {
        let uri_str = uri.to_string();
        let source = match self.document_map.get(&uri_str) {
            Some(s) => s.clone(),
            None => return,
        };

        let client = self.client.clone();
        let workspace_root = self.workspace_root.read().await.clone();

        // Determine whether this is a project-mode or standalone analysis
        let file_path = uri.to_file_path().ok();
        let display_path = file_path.as_ref()
            .map(|p| p.display().to_string())
            .unwrap_or_else(|| uri_str.clone());

        let result = tokio::task::spawn_blocking(move || {
            // Try project mode if workspace_root has writ.toml
            if let Some(ref root) = workspace_root {
                if root.join("writ.toml").exists() {
                    return crate::analysis_host::AnalysisHost::analyze_project(
                        root,
                        Some(&display_path),
                    );
                }
            }
            // Fallback: standalone analysis
            crate::analysis_host::AnalysisHost::analyze_standalone(source, display_path)
        })
        .await;

        match result {
            Ok(analysis_result) => {
                // Group diagnostics by FileId and publish per-URI
                self.publish_grouped_diagnostics(&uri, &analysis_result).await;
            }
            Err(e) => {
                // spawn_blocking panicked — log but don't crash
                eprintln!("writ-lsp: analysis panicked: {e:?}");
            }
        }
    }
}
```

**publish_grouped_diagnostics method:**

This is critical for LSP-08 (cross-file diagnostics). The method must:
1. Build a HashMap<FileId, Url> from `analysis_result.file_sources` (mapping each FileId's display_path to a Url).
2. Build a HashMap<FileId, &str> for source text lookup.
3. For each unique FileId that has diagnostics: convert all its diagnostics via `convert::writ_diag_to_lsp`, then call `client.publish_diagnostics(file_uri, lsp_diags, None)`.
4. For files that previously had diagnostics but now have zero: publish empty vec to clear stale squiggles. Track "last published URIs" in a `DashMap<String, ()>` field on Backend (`published_uris`) and clear any URI not in the current result.

For standalone mode (single file), all diagnostics go to the triggering URI. For project mode, diagnostics are distributed to their respective file URIs.

The `uri_for_file` closure passed to `writ_diag_to_lsp` maps FileId to Url using the FileId->Url HashMap. The `source_for_file` closure maps FileId to source text.

Add a `published_uris: DashMap<String, ()>` field to Backend to track which URIs have published diagnostics, enabling stale diagnostic clearing.

```rust
//! writ-lsp: Language server for the Writ scripting language.
//!
//! Speaks LSP over stdio. Launched by the VS Code extension (writ-vscode).

use dashmap::DashMap;
use tower_lsp::{LspService, Server};

mod analysis_host;
mod backend;
mod convert;

use backend::Backend;

#[tokio::main]
async fn main() {
    let stdin = tokio::io::stdin();
    let stdout = tokio::io::stdout();

    let (service, socket) = LspService::new(|client| Backend {
        client,
        document_map: DashMap::new(),
        workspace_root: tokio::sync::RwLock::new(None),
        published_uris: DashMap::new(),
    });

    Server::new(stdin, stdout, socket).serve(service).await;
}
```

Note: The `main.rs` uses `mod` declarations (not `use writ_lsp::`) because it is the binary entrypoint. The `lib.rs` provides the public API for tests.

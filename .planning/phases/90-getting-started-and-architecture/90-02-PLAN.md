    Write a compiler pipeline overview page. Per CONTEXT.md locked decision: "Architecture page uses prose + table/diagram only, no code snippets (code belongs in cargo doc)."

    Structure:
    - `# Compiler Pipeline` as H1
    - Brief intro: The Writ compiler transforms `.writ` source files into `.writc` binary modules through a 5-stage pipeline.
    - `## Pipeline Stages` — a table showing the 5 stages with columns: Stage, Name, Input, Output, Crate. Use "codegen" as the stage name per requirement wording (note it corresponds to the `emit` module internally):

      | Stage | Name | Input | Output | Crate |
      |-------|------|-------|--------|-------|
      | 1 | Parse | `.writ` source | CST (concrete syntax tree) | `writ-parser` |
      | 2 | Lower | CST | AST (abstract syntax tree) | `writ-compiler` (lower) |
      | 3 | Resolve | AST | Resolved AST (names bound) | `writ-compiler` (resolve) |
      | 4 | Typecheck | Resolved AST | Typed AST (types verified) | `writ-compiler` (check) |
      | 5 | Codegen | Typed AST | `.writc` binary module | `writ-compiler` (emit) |

    - One paragraph per stage explaining what it does (2-3 sentences each, prose only, no code):
      - **Parse**: Tokenizes source with a logos-based lexer and builds a concrete syntax tree using chumsky combinators. Lives in the `writ-parser` crate.
      - **Lower**: Transforms the CST into an abstract syntax tree, desugaring constructs like format strings, dialogue blocks, and entity declarations into canonical forms. Lives in the `writ-compiler` `lower` module.
      - **Resolve**: Performs name resolution, binding identifiers to definitions. Builds a definition map and resolves imports, use declarations, and qualified paths. Lives in the `writ-compiler` `resolve` module.
      - **Typecheck**: Verifies type correctness, infers types where needed, checks contract conformance, and validates function signatures. Lives in the `writ-compiler` `check` module.
      - **Codegen**: Emits the binary `.writc` module format — generates IL instructions, metadata tables, and the 200-byte module header. Lives in the `writ-compiler` `emit` module. (Note: called "emit" in source, "codegen" in documentation.)
    - `## Pipeline Integration` — brief paragraph: the `writ-cli` crate orchestrates the pipeline in `pipeline.rs`, calling each stage in sequence. `writ compile` runs the full pipeline on a single file; `writ build` runs it for all sources in a project.

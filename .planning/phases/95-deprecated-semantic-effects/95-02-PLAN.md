  <action>
    1. In `hover.rs`, add a private helper:
       ```rust
       fn deprecation_notice(def_id: DefId, type_env: &TypeEnv) -> Option<String> {
           type_env.deprecated_items.get(&def_id).map(|msg| {
               if msg.is_empty() {
                   "**Deprecated**".to_string()
               } else {
                   format!("**Deprecated:** {}", msg)
               }
           })
       }
       ```

    2. In `hover_text_for_expr`: For each arm where a `DefId` is available (Call with callee_def_id, Var with def_id, New with target_def_id, etc.), call `deprecation_notice()`. If Some, prepend it to the hover text with a `\n\n` separator. The pattern: build the normal hover text first, then if deprecated, prepend the notice.

    3. In `hover_text_for_def`: Same pattern — the `def_id` parameter is available directly. Prepend deprecation notice if present.

    4. Write LSP integration tests in `test_protocol.rs`:

       **Test: deprecated_hover** — Create a Writ source with `[Deprecated("use bar instead")] fn foo() -> void {}` and a call to `foo()`. Send a hover request at the `foo()` call site. Assert the hover response contains "Deprecated" and "use bar instead".

       **Test: deprecated_diagnostic** — Same source. Send textDocument/didOpen, wait for diagnostics. Assert at least one diagnostic has severity = WARNING (value 2) and message contains "deprecated" and "use bar instead". Note: This test verifies the existing severity mapping pipeline works for W0006 — no new LSP code is needed for the squiggle, just confirm it works.

       Follow the existing test patterns in test_protocol.rs (initialize, open document, send request, assert response). The test source needs TWO files to trigger cross-file deprecation (same-file is suppressed). Check how existing tests handle single vs multi-file — if the harness only supports single-file, the diagnostic test may need to verify that the LSP compiles and returns W0006 in a multi-file project, OR test against a project directory fixture.

       If multi-file LSP testing is impractical with the current harness, write a single-file test that verifies hover shows the deprecation notice (hover works on declaration sites regardless of self-suppression), and add a comment noting that the diagnostic squiggle is integration-tested via the compiler tests in Plan 01.

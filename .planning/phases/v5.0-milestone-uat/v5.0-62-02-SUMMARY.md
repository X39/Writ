# Phase v5.0 Plan 62-02: DAP Breakpoint PC Coordinate Fix Summary

**LoadedModule now stores byte_offsets per method body, and execute_one translates instruction index to byte offset before all debug hook calls, fixing the DAP breakpoint PC coordinate mismatch**

## Performance

- **Duration:** ~5 min
- **Started:** 2026-03-17T12:20:00Z
- **Completed:** 2026-03-17T12:26:34Z
- **Tasks:** 1
- **Files modified:** 2

## Accomplishments

- Added `byte_offsets: Vec<Vec<u32>>` field to `LoadedModule` (parallel to `decoded_bodies`)
- Changed `decode_and_reindex` to return `(Vec<Instruction>, Vec<u32>)` — byte offsets are now preserved through the decode pipeline instead of discarded
- In `execute_one`, `byte_pc` is computed from `module.byte_offsets[method_idx][pc]` before any debug hook call
- `lookup_source_location` and `before_instruction` both now receive `byte_pc` (byte offset) instead of `pc` (instruction index)
- `SuspendReason::Breakpoint` and `SuspendReason::DebugStep` store `byte_pc` in the `pc` field
- All 88 writ-runtime tests pass; all 7 writ-dap tests pass

## Task Commits

Each task was committed atomically:

1. **Task 1: Store byte_offsets on LoadedModule and translate in execute_one** - `c349f24` (feat)

## Files Created/Modified

- `writ-runtime/src/loader.rs` - Added `byte_offsets` field to `LoadedModule`, changed `decode_and_reindex` return type to tuple, updated `from_module` to collect byte offsets, updated all test call sites with offset assertions
- `writ-runtime/src/dispatch/mod.rs` - Added `byte_pc` computation from `module.byte_offsets`, replaced `pc as u32` with `byte_pc` in all debug hook calls

## Decisions Made

- `byte_offsets` stored on `LoadedModule` parallel to `decoded_bodies` — no per-instruction overhead, O(1) Vec index lookup at dispatch time
- `byte_pc` computed with `.get().and_then().copied().unwrap_or(0)` — graceful fallback to byte 0 rather than panic on out-of-bounds (matches behavior of `lookup_source_location` returning `(0,0)` on bad input)
- `frame.pc += 1` continues to use instruction index (correct — stepping is index-based); only the debug reporting path translates to byte offset

## Deviations from Plan

None - plan executed exactly as written.

## Issues Encountered

None. The fix was straightforward: `decode_and_reindex` already computed `byte_offsets` internally but discarded them. Surfacing that Vec through the return type and storing it on `LoadedModule` was the minimal change needed.

## Next Phase Readiness

- Breakpoints can now match at runtime: `BreakpointTable.lookup(method_idx, byte_pc)` receives the same byte offset that `SourceSpan.pc` stores
- `lookup_source_location` now correctly maps byte offsets to source lines for step reporting
- UAT test 9 (breakpoints not hit) is now unblocked at the runtime level
- Tests 10 (variables panel) and 11 (stack trace) are unblocked as stepping now correctly reports source lines

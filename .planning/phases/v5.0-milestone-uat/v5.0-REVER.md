### 1. Diagnostics on Top-Level Parse Error (was UAT #4)
expected: Introduce a syntax error at the top level of a .writ file (outside any function). A red squiggle appears under the error location within 1-2 seconds. The Problems panel shows the error.
result: issue
reported: "Top-level `asd asd asd` (lines 1 and 5) produce no diagnostics; only function-interior errors (line 3) show squiggles. Parser recovery at item level swallows top-level garbage without emitting errors."
severity: major

### 2. Cross-File Diagnostics with writ.toml (was UAT #6)
expected: In a multi-file project (with writ.toml), reference a definition from another file. Diagnostics work correctly across files — errors appear in the right file, hover/completions work on cross-file symbols.
result: pass

### 3. Hover Shows Type on Declarations (was UAT #7)
expected: Hover over a variable name in a `let` binding — tooltip shows the variable's type (not void). Hover over a function parameter name — tooltip shows the parameter's type. Works both with and without writ.toml.
result: issue
reported: "With writ.toml present: hovering let binding always outputs the function body return type. Hovering function args outputs void. Hovering function variables outputs <error> type. Hovering variable usage shows actual type. Hovering fn declaration (fn abc) returns function result instead of signature/docs. Hovering function calls outputs <error> for non-standard functions."
severity: major

### 4. Go-to-Definition on Type Annotations (was UAT #8)
expected: Ctrl+click (F12) on a type name in a variable declaration (e.g., `let x: MyStruct = ...` — click on `MyStruct`) jumps to the struct/entity/enum declaration. Also works on `new X` expressions.
result: issue
reported: "Types and variables both fail. Only function calls work."
severity: major

### 5. Find References from Declaration Site (was UAT #9)
expected: Place cursor on a function/struct/entity name at its declaration (e.g., `fn foo` — cursor on `foo`). Shift+F12 shows all references including the declaration itself.
result: issue
reported: "For functions: pass. For everything else: fail (might be related to types showing as <error>)"
severity: minor

### 6. Signature Help on Incomplete Source (was UAT #12)
expected: Type a function name followed by `(` — a parameter hint popup appears showing parameter names and types. Works even before typing the closing `)`. As you type commas between arguments, the active parameter highlights.
result: pass

### 7. Entity vs Struct Color Distinction (was UAT #13)
expected: In a file with both `struct Foo {}` and `entity Bar {}`, entity name "Bar" is highlighted with a visually distinct color from struct name "Foo" (entity uses teal/support.class color, struct uses default type color).

reported: "Color is the same for identifiers of struct, entity and class. Keywords struct and entity have the same color. class keyword is default text-white (not highlighted as keyword)."
severity: cosmetic

### 8. Launch Debugger (was UAT #16)

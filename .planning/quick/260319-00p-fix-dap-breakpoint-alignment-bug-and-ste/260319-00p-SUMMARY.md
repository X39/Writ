# Phase quick Plan 260319-00p: Fix DAP Breakpoint Alignment Bug and Step-Into Summary

**One-liner:** Pushed source spans for tail expressions in the block emitter so every method has debug info, fixing breakpoint snapping to wrong methods and step-into landing at line 0.

## What Was Done

### Task 1: Fix source span emission for tail expressions

**File:** `writ-compiler/src/emit/body/expr/mod.rs` (lines 117-125)

**Root cause:** The block expression emitter had two code paths for the last statement in a block:
1. Non-tail statements go through `emit_stmt`, which pushes a source span on line 35 of `stmt.rs`
2. Tail expressions (last `TypedStmt::Expr`) bypassed `emit_stmt` and called `emit_expr` directly — without pushing a source span

For functions like `fn test() { log::info("test"); }` (single-statement body = tail expression), this meant zero source spans were emitted. The `BreakpointTable` had no entries for those methods.

**Fix:** In the `TypedStmt::Expr { expr: last_expr, .. }` destructuring pattern, also capture `span`, then push `(instr_idx, *span)` to `emitter.source_spans` before calling `emit_expr`. This mirrors exactly what `emit_stmt` does on stmt.rs:35.

```rust
// Before (broken):
if let crate::check::ir::TypedStmt::Expr { expr: last_expr, .. } = last {
    for stmt in rest { emit_stmt(emitter, stmt); }
    emit_expr(emitter, last_expr)  // no span pushed!

// After (fixed):
if let crate::check::ir::TypedStmt::Expr { expr: last_expr, span, .. } = last {
    for stmt in rest { emit_stmt(emitter, stmt); }
    let instr_idx = emitter.instructions.len() as u32;
    emitter.source_spans.push((instr_idx, *span));  // mirrors emit_stmt:35
    emit_expr(emitter, last_expr)
```

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Test expected wrong SuspendReason variant for step completion**

- **Found during:** Task 2 — first test run
- **Issue:** Initial test asserted `SuspendReason::DebugStep` for a step-into stop, but `DebugHost::before_instruction` always returns `DebugAction::Break` (for both breakpoints and steps), so the runtime always stores `SuspendReason::Breakpoint`. `DebugStep` would require the host to return `DebugAction::StepInto`/`StepOver`/`StepOut`.
- **Fix:** Changed the step-into test to accept both `Breakpoint` and `DebugStep` variants, extracting `(line, method_idx)` from either. The meaningful assertion is the stop location (line 2, method 0), not the enum variant. Added a comment explaining why `Breakpoint` is the expected variant here.
- **Files modified:** `writ-dap/tests/test_debug_session.rs`
- **Commit:** 44ca236 (included in same commit as the tests)

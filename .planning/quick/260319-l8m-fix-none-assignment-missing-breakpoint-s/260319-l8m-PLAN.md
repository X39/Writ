<objective>
Fix two related DAP debugging bugs:

1. **None assignment missing breakpoint span**: When `let n: int? = None;` or `let n: int? = null;` is compiled, the `None` value resolves to `TypedExpr::Var { name: "None" }` which hits the `Var` branch in `emit_expr`. This branch only does a register lookup/allocation and emits NO instruction (`LoadNull` is never generated). Since no instruction is emitted, the source span recorded by `emit_stmt` (at the current instruction index) collides with the NEXT statement's first instruction, making the breakpoint table unable to resolve this line.

2. **Unwrap halt-on-fail in debug mode**: When `n.unwrap()` fails at runtime (because n is None), the VM calls `execute_crash` which sets `TaskState::Cancelled` and unwinds the call stack. In `run_until_stop`, `TaskState::Cancelled` triggers a `Terminated + Exited` event sequence, immediately ending the debug session. The user never sees the crash or gets to inspect state. During debug sessions, a failed unwrap (or any crash) should trigger a `Stopped` event with reason "exception" so the user can inspect the crash.

Purpose: Make DAP debugging reliable for Option/Result workflows.
Output: Fixed emitter, updated debug host, updated golden tests.
</objective>

When the variable name is "None" and is not found in `emitter.locals` (meaning it's the builtin None constructor, not a user-defined variable shadowing it), emit `Instruction::LoadNull { r_dst }` and return the register. This matches what the builtin constructor path does in `builtins.rs` lines 170-173.

The fix:
```rust
TypedExpr::Var { name, ty, .. } => {
    if let Some(&reg) = emitter.locals.get(name) {
        reg
    } else if name == "None" {
        // Standalone None (not a call) — emit LoadNull.
        // This handles `let x: int? = None;` and `let x: int? = null;`
        // (null is lowered to Option::None path, then resolved to Var "None").
        let r_dst = emitter.alloc_reg(*ty);
        emitter.emit(Instruction::LoadNull { r_dst });
        r_dst
    } else {
        emitter.alloc_reg(*ty)
    }
}
```

TypedExpr::Path { segments, ty, .. } => {

**Step 2: Detect crash in run_until_stop** in `writ-dap/src/server/inspection.rs`:

In `run_until_stop`, the `TaskState::Cancelled` arm (lines 110-117) currently sends `Terminated + Exited` unconditionally. Change this to check for crash_info first. When a crash is detected, send a `Stopped` event with reason "exception" instead of terminating.

Replace the `Some(TaskState::Completed) | Some(TaskState::Cancelled)` arm with:

```rust
Some(TaskState::Cancelled) => {
    // Check if this was a runtime crash (unwrap on None, etc.).
    // In debug mode, halt so the user can inspect the crash.
    if let Some(crash) = runtime.crash_info(task_id) {
        let crash_msg = crash.message.clone();
        // Send crash message as output event first
        let _ = self.server.send_event(Event::Output(events::OutputEventBody {
            output: format!("Runtime crash: {}\n", crash_msg),
            category: Some(types::OutputEventCategory::Stderr),
            ..Default::default()
        }));
        // Send stopped event with exception reason
        let thread_id = self.task_id.map(|t| t.index as i64).unwrap_or(0);
        let _ = self.server.send_event(Event::Stopped(events::StoppedEventBody {
            reason: types::StoppedEventReason::Exception,
            description: Some(crash_msg.clone()),
            thread_id: Some(thread_id),
            preserve_focus_hint: None,
            text: Some(crash_msg),
            all_threads_stopped: Some(true),
            hit_breakpoint_ids: None,
        }));
        return;
    }
    // Non-crash cancellation: terminate normally.
    let _ = self.server.send_event(Event::Terminated(Some(
        events::TerminatedEventBody { restart: None },
    )));
    let _ = self.server.send_event(Event::Exited(events::ExitedEventBody {
        exit_code: 0,
    }));
    return;
}
Some(TaskState::Completed) => {
    let _ = self.server.send_event(Event::Terminated(Some(
        events::TerminatedEventBody { restart: None },
    )));
    let _ = self.server.send_event(Event::Exited(events::ExitedEventBody {
        exit_code: 0,
    }));
    return;
}
```

Note: Split the `Completed | Cancelled` arm into separate arms. `Completed` always terminates. `Cancelled` checks for crash_info first.

**Important**: The call stack is already unwound by `execute_crash` at this point, so the user won't be able to inspect local variables of the crashed frame. However, the crash message and output log are visible, and the session stays alive for the user to see the error rather than the debug session abruptly disappearing. This is the correct behavior -- the DAP spec's "exception" stopped reason is meant exactly for this.

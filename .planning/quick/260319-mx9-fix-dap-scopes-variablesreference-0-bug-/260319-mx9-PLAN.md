<objective>
Fix the DAP scopes variablesReference:0 bug that prevents VSCode from requesting variables.

Purpose: When task_idx=0 and frame_idx=0 (the common case for single-task debugging),
`make_variables_ref(0, 0)` returns 0. The DAP spec defines variablesReference=0 as
"no children / not expandable", so VSCode never sends a `variables` request and the
Locals scope appears empty. The fix adds a +1 offset to the packed reference so the
result is always non-zero, and subtracts 1 when unpacking.

Output: Fixed `make_variables_ref`/`unpack_variables_ref` in variables.rs, updated unit
tests, strengthened integration test assertion.
</objective>

```rust
/// Pack (task_idx, frame_idx) into a single DAP `variablesReference` i64.
pub fn make_variables_ref(task_idx: u32, frame_idx: u32) -> i64 {
    ((task_idx as i64) << 32) | (frame_idx as i64)

pub fn unpack_variables_ref(r: i64) -> (u32, u32) {

}
```

   The DAP spec reserves variablesReference=0 for "no children / not expandable".

```rust
pub fn make_variables_ref(task_idx: u32, frame_idx: u32) -> i64 {
    (((task_idx as i64) << 32) | (frame_idx as i64)) + 1
```

2. `unpack_variables_ref`: Subtract 1 before unpacking to reverse the offset.

```rust
pub fn unpack_variables_ref(r: i64) -> (u32, u32) {
    let r = r - 1;
    ((r >> 32) as u32, (r & 0xFFFF_FFFF) as u32)
}
```

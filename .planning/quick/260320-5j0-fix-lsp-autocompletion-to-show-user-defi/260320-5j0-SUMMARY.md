# Quick Task 260320-5j0: Fix LSP Autocompletion for Private Defs and New-Keyword Detail

**One-liner:** Fixed LSP identifier and new-keyword completions to include file-private user-defined types/fns from def_map.file_private, and added struct field detail text to constructable-type completions.

## What Was Built

Two bugs in LSP autocompletion were fixed:

**Bug 1: Non-pub user-defined types/functions missing from completions.**
Both `build_identifier_completions` and `build_new_keyword_completions` previously only iterated `def_map.by_fqn` (which contains only public definitions). Non-pub structs, enums, functions, entities and other user-defined defs stored in `def_map.file_private` were never surfaced in completions.

**Bug 2: New-keyword completions had no detail metadata.**
Completions after `new ` showed only the type name. Users had no visibility into the struct's fields (names and types) without manually looking them up.

## Changes Made

### writ-lsp/src/queries/completion.rs

**`build_identifier_completions`:** Added section 6 that iterates `def_map.file_private.values()` after the public `by_fqn` section. Each private definition gets the same kind/sort_prefix logic as public defs, with the same synthetic-entry and Impl-block filters.

**`build_new_keyword_completions`:**
- Signature changed from `(def_map, _interner)` to `(def_map, interner, type_env)` — the type_env is needed to look up struct fields and entity fields.
- Added `detail` field to all constructable-type completion items (both public and private), populated via new helper.
- Added a file_private loop (same constructable-type filter: Struct/ExternStruct/Class/ExternClass/Entity).

**`build_type_detail` (new helper function):** Generates a human-readable detail string:
- For structs/classes: `"struct { field1: Type1, field2: Type2 }"` using `type_env.struct_fields`
- For entities: `"entity { field1: Type1 }"` using `type_env.entity_fields`
- Falls back to `"struct"` or `"entity"` when fields aren't in the type_env yet

### writ-lsp/src/backend.rs

Updated the `identifier_completion` method's new-keyword branch to extract `type_env` from the cache entry alongside `typed_ast` and `ty_interner`, and pass it to `build_new_keyword_completions`.

### writ-lsp/tests/test_protocol.rs (E2E tests added)

- **`test_completion_shows_private_struct`:** Opens a document with a non-pub `SomeStruct` and verifies it appears in identifier completions with kind STRUCT (22) and sortText starting with `"0_"`.
- **`test_completion_after_new_shows_private_struct_with_detail`:** Opens a document with a non-pub `Point { x: int, y: int }` struct and verifies it appears after `new ` with detail text containing `"x: int"` and `"y: int"`.

### writ-lsp/src/queries/completion.rs (unit tests added)

- **`test_identifier_completions_includes_file_private`:** Verifies private `Foo` struct and private `bar` fn appear alongside public `main` fn in identifier completions.
- **`test_new_keyword_completions_includes_file_private`:** Verifies both `Priv` (private) and `Pub` (public) structs appear in new-keyword completions, and that detail text contains their respective fields.

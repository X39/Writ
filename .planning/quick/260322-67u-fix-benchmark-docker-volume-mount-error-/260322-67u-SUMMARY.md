# Quick Task 260322-67u: Fix benchmark Docker volume mount error on Windows

## Problem

`run.ps1` used a PowerShell 6+ ScriptBlock syntax in `-replace` to convert Windows drive paths (`D:\`) to Unix-style (`/d/`). On Windows PowerShell 5.1, the ScriptBlock was silently stringified, leaving the `D:` colon in the path. Docker then parsed `-v "D:/path:/results"` as three colon-separated fields: host=`D`, container=`/path`, mode=`/results` → `invalid mode: /results`.

`run.sh` MINGW branch unconditionally converted to `/mnt/d/path` format, which is only valid for Podman's WSL backend, not Docker Desktop.

## Changes

### run.ps1
- Removed broken Unix path conversion entirely
- Docker Desktop on Windows handles Windows paths natively (`D:/path:/container`)
- Just convert backslashes to forward slashes for consistency

### run.sh
- Split MINGW branch: Docker uses MINGW-native `/d/path`, Podman uses `/mnt/d/path`
- Both still use `MSYS_NO_PATHCONV=1` and `//results` double-slash trick

## Verification

Run `.\benchmark\runner\run.ps1` on Windows with Docker Desktop — should mount results volume correctly.

# Browser and Web Worker Runtime

`writ-runtime-wasm` runs precompiled `.writc` modules on `wasm32-unknown-unknown`. It is a boundary adapter over `writ-runtime`; it does not port the compiler, CLI, project filesystem, LSP, DAP, or extension. Compile source ahead of time with the native CLI. For native Rust embedding, use [Runtime Integration](runtime-integration.md); that API remains unchanged.

## Build

```console
rustup target add wasm32-unknown-unknown
cargo install wasm-pack
wasm-pack build writ-runtime-wasm --target web --out-dir ../examples/wasm-runtime/pkg
```

`wasm-pack` is the only packaging tool required. Its generated output is not committed. The wrapper owns decoded modules, heap, scheduler, tasks, and callbacks until `WritVm.free()` (generated by `wasm-bindgen`) or JavaScript garbage collection releases it.

## JavaScript and TypeScript API

```js
import init, { WritVm } from "./pkg/writ_runtime_wasm.js";

await init();
const vm = new WritVm();
vm.addLibrary(libraryBytes); // optional; repeat before loadModule
vm.setLogCallback((level, message) => console.log(level, message));
vm.setHostCallback((request) => handleRequest(request));
vm.loadModule(userModuleBytes);
const task = vm.spawn("main", []);
const tick = vm.tick(1 / 60, 10_000);
```

| Method | Result |
|---|---|
| `addLibrary(Uint8Array)` | Queues a compiled library. Must precede `loadModule`. |
| `loadModule(Uint8Array)` | Validates, decodes, links, and owns the user module. The built-in runtime is automatic. |
| `setHostCallback(function)` | Registers one request dispatcher. |
| `setLogCallback(function)` | Registers `(level, message)` delivery for Writ logs. |
| `spawn(name, values)` | Returns `{ index, generation }`. |
| `tick(deltaTime, instructionBudget)` | Returns `{ status, pendingRequests }`; budget must be positive. |
| `pendingRequests()` | Returns requests that remain deferred. |
| `resolveRequest(id, response)` | Supplies a final response and makes the task ready. |
| `taskState(task)` | `ready`, `running`, `suspended`, `completed`, or `cancelled`. |
| `returnValue(task)` | A wire value after completion, otherwise `undefined`. |
| `taskError(task)` | A formatted Writ stack trace for a cancelled task. |
| `lastError()` | The last host-resolution boundary error, if any. |

Unknown or stale task handles and request IDs throw an `Error`. Reloading replaces runtime state and invalidates old handles. The public Rust wire types are `WireValue`, `WireRequest`, `WireOperation`, `WireResponse`, and `WireHandle`. The exported `WritVm` is WASM-only; native programs should use `Runtime` and `RuntimeHost`.

## Values

Values are tagged plain objects. No pointer, heap reference, trait object, or borrowed Rust value crosses the boundary:

```ts
type WritValue =
  | { kind: "void" }
  | { kind: "int", value: string }
  | { kind: "float", value: number }
  | { kind: "bool", value: boolean }
  | { kind: "string", value: string }
  | { kind: "entity", index: number, generation: number }
  | { kind: "opaque", display: string };
```

Integers use signed decimal strings so all 64 bits survive JavaScript's number limit. Strings are copied into or out of the VM heap. `opaque` values are inspection-only and cannot be passed back; arrays, delegates, and arbitrary Writ objects are intentionally not ABI handles. Entity handles retain their index and generation.

## Host requests and responses

Every request has `{ id, task: {index, generation}, type, ...fields }`.

| `type` | Additional fields |
|---|---|
| `externCall` | `name`, `externIndex`, `args` |
| `entitySpawn` | `typeIndex` |
| `fieldRead` | `entity`, `fieldIndex` |
| `fieldWrite` | `entity`, `fieldIndex`, `value` |
| `getComponent` | `entity`, `componentTypeIndex` |
| `initEntity`, `destroyEntity` | `entity` |
| `getOrCreate` | `typeIndex` |
| `join` | `targetTask` |

The callback returns one response:

```ts
type HostResponse =
  | { kind: "value", value: WritValue }
  | { kind: "entity", index: number, generation: number }
  | { kind: "confirmed" }
  | { kind: "deferred" }
  | { kind: "error", message: string };
```

An immediate response is automatically delivered after the core tick returns. `deferred` keeps the task suspended. Retain the request ID, perform asynchronous work, then call `resolveRequest(id, finalResponse)`. A final response cannot be `deferred`. JavaScript exceptions become host errors; malformed responses produce boundary errors. Writ `log::*` externs bypass the request callback and go to the log callback.

## Scheduling and Workers

Always provide a finite instruction budget:

```js
function frame(now) {
  vm.tick(now / 1000, 10_000);
  if (!isTerminal()) requestAnimationFrame(frame);
}
requestAnimationFrame(frame);
```

A Worker can use the same API with `setTimeout(run, 0)` and post status/log messages to its owner. `WritVm` is not transferable: construct and use it entirely in the thread that owns its WASM instance. The wrapper never uses blocking browser APIs or an unbounded loop. Callbacks run after a core tick rather than re-entering an executing Rust VM frame.

## Libraries, security, and limitations

Call `addLibrary` for each precompiled dependency in dependency order before `loadModule`. The built-in runtime module is always injected. Dynamic native-library imports, ambient filesystem/network access, and native project loading are unavailable. Expose capabilities explicitly through the host callback and validate names, arguments, entity generations, URLs, and user-controlled data.

Only precompiled execution is supported. Browser source compilation is deliberately not bundled, keeping compiler size and stack requirements out of the download. Heap objects other than strings are opaque; design host APIs around primitives, strings, and entity handles.

## Sample

From the repository root:

```console
cargo run -p writ-cli -- compile examples/wasm-runtime/sample.writ --output examples/wasm-runtime/sample.writc
wasm-pack build writ-runtime-wasm --target web --out-dir ../examples/wasm-runtime/pkg
python -m http.server 8000 --directory examples/wasm-runtime
```

Open `http://localhost:8000`. The [sample source](../../../examples/wasm-runtime/README.md) demonstrates immediate and deferred extern calls, logging, bounded animation-frame ticks, and the final value.

## Troubleshooting

- **Fetch/CORS failure:** serve over HTTP; do not use `file://`.
- **MIME error:** use a server that serves `.js` as JavaScript and `.wasm` as `application/wasm`.
- **`no module loaded`:** call `loadModule` before `spawn`.
- **load/link error:** compile user and library modules from the same repository version and add all libraries first.
- **task remains suspended:** inspect `pendingRequests()` and resolve every deferred request.
- **UI freezes:** lower the instruction budget; do not replace scheduled ticks with a synchronous loop.
- **opaque value rejected:** do not retain or send internal VM heap objects across the boundary.
